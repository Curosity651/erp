## 2. 系统角色和责任边界

系统分为三层：

1. 海外仓平台：管理仓库、库位、收货、上架、库存、下架、拣货、退货质检、盘点、报废、WMS 服务商合同及平台服务费。
2. WMS 服务商：管理名下 ERP 货主、物流产品、货主充值和物流产品收入，并向海外仓平台充值和支付仓储作业费用。
3. ERP 货主：管理店铺、SKU、采购、国内到海外仓物流、平台订单、FBO 库存、库存资产和应付账务。

主要租户关系：

- 海外仓平台租户：`-1 / OVERSEAS_PLATFORM`
- WMS 服务商示例：`5 / WMS_FIRST`
- ERP 货主示例：`6 / JHIN`，其 `parent_wms_tenant_id=5`

所有库存、订单、费用查询都必须保持货主和 WMS 服务商的数据隔离。

## 3. 已确认的库存与库位新架构

### 3.1 核心原则

- 已废弃“固定排×列×层×托位”的几何仓库模型。
- 已废弃业务层面的托盘、托位和库存批次概念。
- 所有库位都是逻辑位置；每排可以动态增加库位。
- 上架直接选择目标库位，移库直接选择“源库位 → 目标库位”。
- 新库存单一事实来源（SSOT）是 `wms_location_inventory`。
- 旧 `wms_inventory`、`wms_physical_inventory`、托盘和托位链路只能作为遗留兼容，不得继续作为新业务读写主表。
- 逻辑库存唯一维度：WMS 服务商、ERP 货主、仓库、库位、内部 SKU、品质。
- `quantity` 是实物总量，`reserved_quantity` 是其中已预占量，可用量为 `quantity - reserved_quantity`。

### 3.2 库位规则

- 仓库只维护排数。
- 每排可以随时新增库位。
- 删除库位前必须清空库存、预占和未完成业务引用。
- 库位维护长、宽、高、最大承重和分区类型。
- 四种基础分区：标准区、暂存区、退货区、不良品区。
- 新建仓库应自动补齐四种分区；不仅初始化当前仓库。
- 暂存区允许多个 WMS 服务商和货主共同使用，库存归属仍由库存行区分。
- 允许不同货主、不同 SKU 在同一库位混放。
- 已被销售履约预占的数量禁止人工移库，只允许移动可用数量。
- 不良品只能存在于不良品区，不允许普通移库，只能走报废。

### 3.3 容量规则

- ERP SKU 必须维护外箱长、宽、高和单箱毛重，否则不能创建相关入库业务。
- 库位容量和承重用于展示、告警和运营判断。
- 当前上架是“事后记录现实”的模式，不再由系统推荐库位或强制推荐数量。
- 即使容量或重量超限，也应允许保存实际上架结果，但必须警告、填写原因并标记库位异常。

## 4. 入库、收货和上架流程

### 4.1 ERP 入库单

- ERP 创建采购或自定义入库单。
- 入库单号应包含货主标识，避免不同货主使用相同外部单号时冲突。
- 货主端每条入库单提供打印按钮，打印后贴在箱子上。
- 同一入库单允许重复 SKU，但收货必须按 `inboundOrderItemId` 写入，不能仅按 SKU 覆盖多行。

### 4.2 海外仓收货

- 可扫描 SKU 逐件增加数量。
- 可在收货详情中扫描完整入库单号，一次填满全部应收数量。
- 不允许前端录入超过应收数量后才在提交时失败；应即时阻止超收。
- 点击确认收货前弹出“确认货物已经收齐”的二次确认。
- 收货必须记录操作员并支持按操作员筛选。
- 收货时支持上传现场照片作为证据。
- 收货完成后可以打印全部内部 SKU 标签及货物对照表。

### 4.3 内部 SKU 标签

- 内部唯一 SKU 由“货主标识 + 原 SKU”组成，例如 `JHIN-ADNZ-001`。
- 仅海外仓平台打印和使用，ERP 货主端仍可看到自己的原始 SKU。
- 标签改为条形码：上方条形码，下方一行小字显示内部 SKU。
- 每箱必贴，不再增加托盘码、货垛码或容器码。

### 4.4 上架

- 收货完成后进入上架补录。
- 按 SKU 汇总展示实收数量。
- 可展开 SKU 图片、外箱尺寸、重量等信息。
- 工人先实际完成摆放，再在系统中选择一个或多个库位补录结果。
- 一种 SKU 可以拆分到多个库位，全部数量都可人工修改。
- 提交前校验各 SKU 分配总数是否等于实收数量；不一致必须明确提示。
- 完成后生成可打印的上架单，不再打印托盘标签。
- 支持下载当前入库单专用 Excel 模板，并由前端解析 Excel 后回填表单；导入本身不直接写数据库，最终仍通过正常提交接口保存。

## 5. 库位库存与库位调整

- 库位库存提供网格视图和列表/树形视图。
- 网格按排展示库位方块，像电池电量一样显示容量占比。
- 点击库位显示货主、服务商、内部 SKU、数量、预占、可用、品质、体积和重量。
- 列表按自然数字顺序排列，不能出现 `A1、A10、A2`。
- 支持按 SKU、分区、仓库、货主和服务商筛选。
- 库位调整以库存行和数量为单位，不再选择托盘或托位。
- 支持物理/逻辑库位之间的任意合法移动，目标库位必须有访问权限。
- 移库必须记录操作员、原因、源库位、目标库位、时间和数量。
- 当前系统曾经实现过托盘移库逻辑，接手时要确保新版页面和接口没有再次调用旧托盘服务。

## 6. 盘点、退货质检和报废

### 6.1 盘点

- 全仓盘点和循环盘点都以库位为任务单位。
- 循环盘点库位按自然顺序排列。
- 专项盘点不应简单按货主生成一个无法落地的大任务。
- 货物混放的情况下，专项盘点应先根据 SKU/货主条件反查实际库位，再以这些库位生成任务。
- 盘点单显示操作员。
- 盘盈的新 SKU 必须先存在 SKU 主数据，并明确货主和目标库位。

### 6.2 退货质检

- 质检完成后同时入库。
- 良品进入退货区。
- 不良品进入不良品区。
- 记录仓库、货主、服务商、操作员、照片和质检结果。
- 新版应写入 `wms_location_inventory`，不得继续写旧托盘或物理批次库存。

### 6.3 报废

- 只能报废当前货主在不良品区的货物。
- 不能从标准区、暂存区或其他货主库存直接报废。
- 报废必须保留操作员、原因、数量和审计记录。

## 7. 新版订单履约和出库流程

### 7.1 已确认的总体方向

- 停用旧“销售出库单”和旧“自定义出库单”作为主流程。
- 新主流程以一个平台订单/一个物理包裹为履约单位。
- 主表是 `wms_fulfillment_order` 及其明细、预占和拣货任务表。
- ERP 订单确认后产生内部“待下架”状态，并预占 `wms_location_inventory`。
- 在真正下架前，ERP 允许取消并释放预占。
- 海外仓下架后向电商平台确认，此后不允许普通取消，后续状态以平台状态为准。
- 人工主动出库仍保留，但必须收紧为“一条订单 = 一个包裹”。

### 7.2 物流产品

- 物流产品由 WMS 服务商创建，所属 ERP 货主可以选择。
- 物流产品是对 ERP 货主销售的标准物流/包装服务，不要求系统自动对接真实承运商。
- 属性至少包含：产品编码、名称、默认费用、币种、详细说明、启用状态。
- 店铺可以配置默认 WMS 仓库和默认物流产品。
- ERP 确认订单时自动带出默认值并允许临时修改。
- 已使用的物流产品不能物理删除，只能禁用。
- 已产生业务后，默认费用不能直接覆盖历史；订单必须保存产品名称、费用和币种快照。
- 签出时允许人工调整最终物流产品费用，但必须记录原因。
- 每个签出订单填写承运方式和跟踪号，仅作记录，不在系统中继续跟踪物流状态。

### 7.3 订单下架

- “订单下架”是独立二级菜单。
- 页面只允许勾选“待下架”订单，已下架复选框置灰。
- 页面不再提供手工“生成拣货任务”按钮。
- 点击确认下架后，按仓库自动拆分并生成一个或多个拣货任务。
- 不同货主订单允许合并在同一拣货任务中，唯一拆分条件是所属仓库。
- 列表显示履约单号、平台订单、平台、货主、物流产品、仓库、收件人、状态和创建时间。
- 支持按日期、货主、物流产品、仓库筛选。
- 第一列和最后一列固定，中间横向滚动，布局参考入库收货。

### 7.4 拣货任务

- “拣货任务”是独立二级菜单。
- 任务列表可以领取任务，进入任务作业页。
- 任务内订单按建议顺序排列，但允许选择任意一单先处理（已选择方案 B）。
- 取货时必须展示库位、内部 SKU、商品 SKU 和应取数量。
- 工人扫描库位码，再扫描箱体内部 SKU 条形码，确认取货。
- 取货与打印平台面单是连续行为：拿到该订单货物后立即打印面单并粘贴，而不是先取完所有货再统一分货。
- 不再依赖固定分货格/格口作为主流程。

### 7.5 两种兼容作业方式

逐单扫描模式：

1. 领取任务。
2. 任意选择待处理订单。
3. 扫描库位和内部 SKU。
4. 确认取货。
5. 打印并核验平台面单。
6. 完成打包。
7. 处理下一单。

整单简化模式：

1. 点击“整单作业”。
2. 弹窗展示任务内所有订单。
3. 打印拣货单。
4. 打印全部平台面单。
5. 工人拿拣货单逐单取货并立即贴面单。
6. 上传整单作业凭证照片。
7. 所有订单满足条件后点击完成任务。

两种模式共享同一状态机和库存扣减，不能重复完成或重复签出。

### 7.6 签出

- 单个订单完成取货、面单和打包后进入待签出。
- 支持批量签出。
- 批量签出只处理所有前置条件均完成的订单。
- 签出时实际扣减库存、释放预占、记录物流产品费用和平台仓储出库费用。
- 假测试订单无法从平台获取真实面单是正常情况，但前端错误提示应可关闭或自动消失。

## 8. 电商平台边界

- 支持 Ozon、Wildberries、Yandex。
- 订单确认/下架需要调用平台接口确认；测试订单无法返回平台结果时可通过测试数据机制验证内部流程，不能污染生产接口逻辑。

- FBS 发出后脱离仓库控制，不继续计入库存资产。
- FBO 从海外仓发出后仍属于货主资产，应通过平台库存快照继续统计数量。
- 海外仓平台不需要展示或运营 FBO 仓内库存；FBO 仅在 ERP 货主端库存和资产中展示。

## 9. 平台财务和资金关系

### 9.1 三类完全不同的财务关系

1. ERP 货主 → 采购供应商：采购应付、首付款和尾款。
2. ERP 货主 → WMS 服务商：充值并消费物流产品费用。
3. WMS 服务商 → 海外仓平台：充值并支付入库、出库、仓储等平台服务费。

这三类资金不能混用一张账或同一组库表。

### 9.2 合同资金

- WMS 服务商与海外仓平台签订仓储服务合同。
- 新建合同必须上传真实 PDF 合同。
- 货架/排数量与实际分配排实时对应，数量为 3 时只能选择 3 个实际排；数量清空时实际排也清空。
- 货架认购费：单排 60,000 元，3 排共 180,000 元。
- 合作满一年、无违约、无欠费、无遗留货物时退还认购费 70%，剩余 30% 为维护和损耗费。
- 仓储押金固定 60,000 元，不随排数变化。
- 认购款是一次性收齐，不按月收取。

### 9.3 月度平台服务对账

- 应收账单只统计当月实际产生的平台仓储作业费用，如按体积入库、出库、仓储等。
- 每月最后一天自动生成正式账单。
- 当月未结束时资金账户可实时展示本月累计流水，但不能提前生成正式月度账单。
- 每张账单提供复核。
- 补充费用和冲减必须登记到具体账单，保留原因、操作人和审计轨迹。
- 不允许直接覆盖原始费用行。
- “服务商资金账户”和“月度服务对账单”在同一页面用两个切换卡片/选项卡展示，不能上下堆叠。

### 9.4 充值与资金流水

- 充值只作系统记录，不真实对接支付平台。
- 充值必须上传付款凭证并经对方审核后入账。
- ERP 货主向 WMS 服务商充值物流产品余额。
- WMS 服务商向海外仓平台充值服务费余额。
- 资金流水按月份树形聚合；第一层展示每月充值、消费和余额变化，展开后显示月内明细。
- 当前月份实时统计。
- 流水类型、业务说明和费用代码必须显示中文。
- 支持选择时间范围导出资金流水。

## 10. 资产与账务业务规则

### 10.1 已确认口径

- 资产价值 = 当前仍受货主控制的商品采购成本 + 国内到海外仓物流资本化成本。
- 采购成本按 SKU、币种分别做加权平均，不做跨币种汇率折算。
- 国内物流费只有物流单确认发货后才资本化。
- FBS 从海外仓签出后不再属于货主资产。
- FBO 库存仍属于货主资产，只统计平台库存数量，不要求系统维护 FBO 仓内可用、预占、库位等细节。
- 暂不追踪 FBO 在途，界面必须明确标记数据缺口。
- 应付账务与资产分开：已付、未付、首付款和尾款不改变货物是否属于资产，只改变应付余额。
- WMS 充值账户不是应付采购账，也不是库存资产，应独立展示。

### 10.2 2026-08-26 最新接口审计结论

存在明确 P1：资产接口仍通过 `RegionStockDataProvider` 读取旧 `wms_inventory`，但当前真实库存已经切换到 `wms_location_inventory`。

当前数据库实测：

- `wms_location_inventory`：6 行，实物总量 24，预占 4，可用 20。
- `wms_inventory`：0 行。
- `wms_fbo_inventory_snapshot`：FBO 总量 12。
- 无采购未发货和国内物流在途时，正确持有总量应为 36；当前接口只能看见 FBO 12，遗漏海外仓 24。

受影响接口：

- `/wms/asset-finance/overview`
- `/wms/asset-finance/procurement-detail`
