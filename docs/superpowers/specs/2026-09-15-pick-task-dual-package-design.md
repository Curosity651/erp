# 拣货任务双文件包设计

## 目标

将拣货任务中的“打印拣货单”改为生成两个任务级 ZIP：俄文仓库包和中文留底包。支持 OZON、WB、YANDEX、MANUAL；生成文件不推进订单或任务状态，不触发发货、签出和计费。

## 入口与交互

- 入口仍为拣货任务详情中的“打印拣货单”。
- 点击后由后端生成文件，前端显示生成进度。
- 成功后提供“下载俄文仓库包”和“下载中文留底包”两个按钮，并尝试依次自动下载。
- 同一任务快照重复点击复用已有文件；任务内容变化后生成新版本。

## 俄文仓库包

包名：`Sklad-<taskNo>-<yyyyMMdd-HHmm>.zip`。

包内结构：

```text
00_Checklist_<yyyyMMdd-HHmm>.pdf
OZON/Pick_List_OZON.pdf
OZON/<shop>/Labels_<shop>.pdf
WB/Pick_List_WB.pdf
WB/<shop>/Labels_<shop>.pdf
YANDEX/Pick_List_YANDEX.pdf
YANDEX/<shop>/Labels_<shop>.pdf
MANUAL/Pick_List_MANUAL.pdf
MANUAL/Labels_MANUAL.pdf
manifest.json
```

仓库包约束：

- 文件名、目录名和可见文案不使用中文；动态店铺名需净化为安全拉丁标识。
- 按平台、店铺分组；拣货单按库位、内部 SKU 排序并汇总数量。
- 标签由现有平台适配器获取；MANUAL 使用系统生成标签。
- 不覆盖、缩放或裁剪平台原标签；平台标签原页直接合并。
- 每个有效任务订单在包内必须恰好对应一个标签页或一组明确归属该订单的标签页。
- 若任一有效订单缺标签、缺任务明细或数量不闭合，则不发布正式仓库包。

## 中文留底包

包名：`拣货任务-<taskNo>-<yyyyMMdd-HHmm>-中文.zip`。

内容：

```text
00_汇总.xlsx
订单与SKU明细.xlsx
跳过与异常.xlsx
manifest.json
文件校验清单.json
```

第一期使用 XLSX 与 JSON 留底，不复制仓库包中的拣货单和标签。汇总记录任务、仓库、拣货员、平台、店铺、订单数、SKU 数和件数；明细记录库位、SKU、计划数量、平台订单号；异常表记录取消、标签失败、明细缺失和校验失败。

## 生成流程

1. 读取任务、任务订单和拣货行，形成不可变快照。
2. 排除已取消任务订单；其余订单必须具有明细且计划数量大于零。
3. 按平台调用现有标签适配器。已成功获取的标签由平台动作幂等记录复用。
4. 下载平台标签字节；MANUAL 在服务端生成标准标签。
5. 生成各平台拣货单和总检查单。
6. 构造 manifest，记录任务快照、文件成员、页数、大小与 SHA-256。
7. 回读 ZIP，校验路径、成员、摘要、订单集合和数量闭环。
8. 两个包均通过后上传私有 OSS，并返回短期签名下载地址。

## 平台隔离

- OZON、WB、YANDEX 共用任务组包合同，但标签获取和标签页校验分别由平台适配器负责。
- 不把 OZON 的 58×40 mm 约束强加给 WB 或 Yandex。
- 混合平台任务仍只生成两个 ZIP，平台文件放在独立目录，禁止合并成一份跨平台标签 PDF。
- 未知平台阻断生成并返回明确订单号，不做猜测或静默跳过。

## 幂等与审计

- 快照摘要由任务 ID、任务更新时间、有效订单状态、拣货行和标签引用共同计算。
- `(task_id, snapshot_hash)` 唯一；相同快照返回同一批次。
- 保存批次号、生成者、生成时间、两个 objectKey、文件摘要和生成状态。
- 生成失败保留错误摘要，但不暴露平台密钥、签名 URL 查询参数或收件人隐私。

## 接口

- `POST /wms/fulfillment-picking/tasks/{id}/print-packages`：创建或复用双包。
- 返回 `batchNo`、`reused`、两个文件名与下载地址、订单数、总件数。
- 继续使用 `wms:outbound-exec:oper` 权限，并校验当前用户为任务操作员。

## 验收

- 四个平台均能进入各自目录，混合任务仍只有两个 ZIP。
- 仓库包中有效订单无缺失、无重复，件数与任务快照一致。
- 中文包不包含标签 PDF，且所有汇总和明细可回读。
- 重复生成同一快照返回相同批次；任务变化后生成新批次。
- 生成动作不会修改履约状态、拣货状态、打包状态、签出状态或费用。
