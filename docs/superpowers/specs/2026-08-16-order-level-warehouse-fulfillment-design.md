# 订单级海外仓履约改造设计

状态：业务方案已确认，等待用户审阅书面规格后进入实施计划

## 1. 改造目标

当前系统先把多个电商平台订单组织成销售出库单，再由海外仓围绕销售出库单执行下架、拣货、分货、打包和签出。该模型增加了不必要的聚合层，也让出库单、平台订单和物理包裹三种概念相互混淆。

本次改造采用订单级仓库履约内核：

- 删除用户可见的销售出库单概念；
- 平台订单在 ERP 确认发货后直接进入海外仓；
- 主动出库保留，但改为一条人工出库订单对应一个包裹；
- Ozon、Wildberries、Yandex 和人工订单共用同一套仓库作业流程；
- 一条订单严格对应一个物理包裹，不支持拆包或合包；
- 批量只发生在拣货任务层，不改变订单和包裹的一对一关系；
- 拣货、面单、打包和签出合并为一个统一作业页面；
- 取消固定分货格和二次分货流程；
- ERP 提交订单时预占库存，仓库签出时正式扣减库存。

## 2. 现有代码冲突

当前代码的实际顺序是：

```text
ERP 订单确认
-> 直接调用平台发货接口
-> ERP 订单变为 SHIPPED
-> 创建销售出库单并关联一个或多个平台订单
-> 销售出库单预占库存
-> 海外仓拣货、分货、打包和签出
```

主要职责目前分散在：

- `OzonOrderConfirmService`、`WbOrderConfirmService`、`YdOrderConfirmService`：ERP 端直接调用平台确认接口；
- `SalesOutboundFacade`：订单占用、销售出库单创建、预占和取消；
- `OutboundPickingService`：围绕销售出库单创建单单或波次拣货任务；
- `SalesOutboundPackageService`：在销售出库单下按平台订单创建包裹；
- `OutboundShippingService`：按包裹签出、扣库存和计费；
- `OutboundPickingPage.vue`、`PickListDrawer.vue`：下架、拣货和分货格；
- `PackShipPage.vue`：平台订单打包签出。

新设计将上述职责围绕订单级履约记录重新组织，不继续隐藏或伪装一张一订单的销售出库单。

## 3. 核心业务约束

### 3.1 一单一包裹

- 一条 Ozon、Wildberries 或 Yandex 平台订单对应一个物理包裹；
- 一条人工出库订单对应一个物理包裹；
- 一个订单可以包含多个 SKU 和多件商品；
- 一个订单不能拆成多个物理包裹；
- 多个订单不能合并成一个物理包裹；
- 一个拣货任务可以包含多个订单，但每个订单独立完成面单、打包、签出和计费。

### 3.2 批量边界

- 批量下架逐单执行，允许部分成功；
- 批量拣货任务只允许选择同一仓库、同一货主的订单；
- 同一拣货任务可以混合 Ozon、Wildberries、Yandex 和人工订单；
- 任务内按订单逐单拣货，不进行汇总拣货后的二次分货；
- 批量签出逐单执行，允许部分成功。

## 4. 数据模型

### 4.1 仓库履约订单

新增 `wms_fulfillment_order`。一条记录同时代表一个仓库履约订单和一个物理包裹。

主要字段：

- `id`、`fulfillment_no`；
- `source_type`：`PLATFORM` 或 `MANUAL`；
- `source_key`：平台订单使用 `ERP_ORDER:<id>`，人工订单使用 `MANUAL:<orderNo>`；
- `erp_order_id`：平台订单对应的 ERP 订单 ID，人工订单为空；
- `erp_tenant_id`、`wms_tenant_id`、`platform_tenant_id`；
- `warehouse_id`；
- `platform`、`shop_id`、`platform_order_id`；
- 人工订单的收件人、电话、地址、关联单号和备注；
- `fulfillment_status`：仓库内部履约状态；
- `platform_stage`、`platform_action_state`、`platform_error`、`retry_count`；
- `label_status`、面单文件标识、面单复核码；
- 物流方式、跟踪号、理论重量和实际重量；
- 拣货、打包、签出操作人和时间；
- 库存扣减状态、费用记录 ID；
- `version`、创建和更新时间。

数据库唯一约束：

```text
UNIQUE(source_key)
UNIQUE(fulfillment_no)
```

平台订单重复提交时返回原履约记录，不重复预占。人工订单号由系统生成并直接作为唯一来源键的一部分。

### 4.2 履约商品快照

新增 `wms_fulfillment_item`：

- `fulfillment_order_id`；
- `erp_order_item_id`，人工订单可为空；
- ERP SKU、内部仓库 SKU；
- 商品名称、图片和平台商品标识；
- 应发数量；
- 已预占、已拣、已返库和已签出数量；
- 创建和更新时间。

履约商品在 ERP 提交时从订单和 SKU 映射生成不可变快照。平台后续同步不能静默修改已提交的仓库需求；发现订单内容变化时进入异常并要求人工处理。

### 4.3 库位库存预占

使用新逻辑库位库存内核的预占表 `wms_inventory_reservation`：

- 直接关联逻辑库位库存 ID；
- 关联履约订单和履约商品；
- 保存预占数量、已拣数量、已签出数量和释放数量；
- 不再保存批次、托盘和托位；
- 使用行锁、条件更新和非负约束防止并发超量预占。

### 4.4 拣货任务关系

拣货任务保留，但关系表改为订单级：

```text
wms_outbound_pick_task
wms_pick_task_fulfillment
wms_outbound_pick_task_line
wms_outbound_scan_event
```

任务明细直接关联履约订单、履约商品、库位库存和预占记录。不再引用销售出库单、物理批次、托盘或托位。

### 4.5 平台动作日志

新增 `wms_fulfillment_platform_action`，记录平台分阶段调用：

- `fulfillment_order_id`；
- `action_type`；
- 请求幂等键；
- 请求摘要和平台响应摘要；
- `PROCESSING/SUCCESS/FAILED/UNKNOWN`；
- 尝试次数、错误、开始和完成时间。

唯一约束：

```text
UNIQUE(fulfillment_order_id, action_type)
```

该表用于处理平台成功但本地事务失败、网络超时后结果未知和重复点击等情况。

### 4.6 店铺默认海外仓

店铺增加默认内部海外仓配置，或建立等价的店铺仓库路由表：

- 一家店铺只能有一个启用的默认内部海外仓；
- 默认仓库必须在当前货主有权使用的仓库范围内；
- ERP 确认窗口自动带出默认仓库；
- 货主可以临时改选其他有权仓库；
- 提交时再次校验仓库授权、服务有效期和 WMS 服务商关系；
- 平台订单中的 Ozon/WB/Yandex 平台仓库标识与本系统 `wms_warehouse.id` 分开保存，禁止混用。

## 5. 状态模型

仓库内部状态：

```text
DRAFT                 草稿，仅人工订单
WAITING_SHELF         待下架，库存已预占，货主可取消
PLATFORM_PROCESSING   平台动作处理中
WAITING_PICK          待取货，仓库已接单
PICKING               取货中
WAITING_PACK          已取货，待面单和打包
PACKED                已打包，待签出
SHIPPED               已签出
CANCEL_RETURNING      已拣商品等待返库
CANCELLED             已取消
EXCEPTION             作业异常
```

平台镜像状态继续保存在 `erp_order.platform_status`、`platform_substatus` 和 `erp_status`，由平台 API 同步。平台同步不得覆盖 `wms_fulfillment_order.fulfillment_status`。

平台订单正常流转：

```text
ERP 确认并预占
-> WAITING_SHELF
-> 海外仓确认下架
-> PLATFORM_PROCESSING
-> WAITING_PICK
-> PICKING
-> WAITING_PACK
-> PACKED
-> SHIPPED
```

人工订单跳过平台处理：

```text
DRAFT
-> 提交并预占
-> WAITING_SHELF
-> 海外仓确认下架
-> WAITING_PICK
-> PICKING
-> WAITING_PACK
-> PACKED
-> SHIPPED
```

关键状态转换使用状态 CAS 和版本号。重复请求不能重复调用平台、预占、扣减库存或计费。

## 6. ERP 平台订单提交

Ozon、Wildberries 和 Yandex 订单页保留原风格。“确认”改为“确认发货”，但不再直接执行完整的平台发货确认。

确认窗口展示：

- 平台订单、店铺和商品数量；
- 店铺配置的默认海外仓；
- 货主有权使用的其他海外仓；
- SKU 映射和商品资料检查；
- 每个 SKU 的需求、可用库存和预计预占；
- 提交后进入待下架且仓库接单后不可取消的提示。

店铺未配置默认海外仓时不静默选择第一家仓库，必须由货主在确认窗口明确选择。

后端事务：

1. 回拉平台最新订单状态；
2. 校验订单仍允许提交；
3. 校验货主、店铺、仓库权限和仓库有效期；
4. 校验 SKU 映射、外箱尺寸和单箱毛重；
5. 生成履约订单和商品快照；
6. 锁定逻辑库位库存并完成预占；
7. 将内部状态设置为 `WAITING_SHELF`。

任一环节失败则全部回滚。库存不足时不创建有效履约任务，也不产生部分预占。

## 7. 人工出库订单

原自定义出库单改为“人工出库订单”，不再使用出库单聚合概念。

人工订单支持：

- 多个 SKU 和多件商品；
- 一个收件人和一个地址；
- 一个物流方式和一个跟踪号；
- 一个物理包裹；
- 关联单号和备注。

人工订单可以保存草稿。正式提交时执行与平台订单相同的仓库权限、SKU 资料和库存预占校验。海外仓下架时不调用平台接口，直接进入待取货。

## 8. 海外仓订单下架

“下架拣货”拆分为“订单下架”和统一“取货签出”。订单下架页面按履约订单展示，不显示销售出库单号。

支持：

- 单个确认下架；
- 批量确认下架；
- 查看平台处理阶段和失败原因；
- 对失败订单单独重试。

批量处理逐单提交。成功订单进入 `WAITING_PICK`，失败订单保持 `WAITING_SHELF` 和库存预占。一个订单失败不回滚其他成功订单。

## 9. 平台分阶段处理

前端呈现统一操作，后端通过平台适配器执行不同阶段。

### 9.1 Ozon

- 下架：执行一包裹组包或发货准备动作；
- 面单：轮询或重试获取平台面单；
- 贴单打包：扫描面单复核码；
- 签出：执行 Ozon 当前配送方式需要的最终动作；
- 需要交接单的店铺和配送方式继续按正式配置处理，不通过仓库名称判断。

### 9.2 Wildberries

- 下架：创建或选择供货、加入订单并进入组装阶段；
- 面单：订单拣齐后获取并打印 WB 面单；
- 签出：订单打包贴单后执行正式交运；
- 如果平台供货包含多个订单，供货的最终关闭必须等待该供货下所有纳入订单满足平台条件。

### 9.3 Yandex

- 下架：只完成仓库内部接单，不提前设置 `READY_TO_SHIP`；
- 拣齐后：设置一个箱子的商品布局；
- 面单：获取并打印该订单面单；
- 贴单打包后：设置 `PROCESSING/READY_TO_SHIP`；
- 签出：执行当前履约模式要求的最终动作。

该顺序遵循 Yandex 官方 FBS 流程：先组包、获取并粘贴面单，再设置 `READY_TO_SHIP`。

参考：`https://yandex.ru/dev/market/partner-api/doc/ru/step-by-step/fbs`

### 9.4 平台失败处理

- 平台明确失败：记录失败原因并允许重试；
- 网络超时或结果未知：先查询平台实际状态，不盲目重复提交；
- 平台成功、本地失败：标记平台阶段成功，后续只补本地步骤；
- 所有重试使用平台动作日志和幂等键。

## 10. 拣货任务

创建任务条件：

- 订单处于 `WAITING_PICK`；
- 同一个仓库；
- 同一个货主；
- 不要求同一平台；
- 订单未加入其他有效拣货任务。

任务可以包含一个或多个订单。任务内始终逐订单作业，不汇总取货后再分货。

拣货单显示：

- 任务号和任务条码；
- 每个订单的独立条码；
- 平台、订单号、SKU 和数量；
- 按自然顺序排列的库位；
- 库位类型、内部 SKU 和商品名称。

现场流程：

```text
扫描任务码
-> 扫描订单码
-> 扫描系统提示的库位
-> 逐件扫描内部 SKU
-> 当前订单全部商品数量相符
-> 获取并打印平台面单
-> 扫描面单条码复核
-> 确认贴单和打包
-> 继续任务中的下一个订单
```

拣货规则：

- 错误库位、错误货主或错误 SKU 立即拒绝；
- 扫描数量不能超过应发数量；
- 每箱内部 SKU 标签扫描一次累计一件；
- 有权限的人工登记必须填写原因；
- 每次操作记录任务、订单、库位、SKU、数量、操作人和时间；
- 多库位商品按少跑库位优先的分配顺序拣货；
- 实际缺货可以重新分配其他库位；
- 已拣商品取消前必须扫码返库。

取消固定分货格、格口占用和平台订单二次分货。

## 11. 统一取货签出页面

原下架拣货的任务执行区和打包签出页面合并为一个“取货签出”页面。

页面包含：

- 待取货、取货中、待面单、待签出、已签出和异常统计；
- 订单号、任务号、平台、货主、仓库、状态和日期筛选；
- 按订单展示的待处理列表；
- 单个或批量创建拣货任务；
- 左侧任务订单列表；
- 右侧当前订单扫码作业区；
- 当前库位、SKU、计划和已拣数量；
- 面单打印、贴单复核、打包和签出操作；
- 已打包订单单个或批量签出。

页面不再显示：

- 销售出库单号；
- 出库单数量；
- 分货格和格口范围；
- 二次分货步骤；
- 托盘、托位和批次。

界面采用已确认的 HTML 原型布局。

## 12. 面单与打包

- 平台面单全部由海外仓调用 Ozon、Wildberries 或 Yandex 接口获取；
- ERP 货主端不再打印平台面单；
- 删除“仓库打印/货主已提供”选择；
- 人工订单由系统生成普通发货标签；
- 当前订单所有商品拣齐后才开放面单打印；
- 面单获取失败不丢失拣货进度，订单保持待面单并允许重试；
- 面单打印后必须扫描允许的面单条码完成复核；
- 商品复核和面单复核均完成后才能确认打包。

## 13. 签出与库存扣减

ERP 提交时只增加预占。拣货扫描只记录商品已经离开库位，不扣减账面现存数量。

签出时逐单执行：

1. 使用状态 CAS 认领签出；
2. 校验商品全部拣齐、面单已复核、订单已打包；
3. 完成平台当前阶段要求的最终动作；
4. 按库位预占明细扣减现存数量和预占数量；
5. 写库存流水和签出记录；
6. 生成出库费用；
7. 更新为 `SHIPPED`。

平台订单自动带出物流方式和跟踪信息。人工订单带出创建时选择的物流方式。理论重量根据 SKU 单箱毛重和数量计算，有权限人员可以按实际称重修改并记录原值、新值、操作人和原因。

## 14. 出库费用

- 费用业务键由旧销售出库单 ID 改为履约订单 ID；
- 同一履约订单只允许生成一次出库费用；
- 签出成功后才计费；
- 保留现有散件、大箱、小件和人工整托计费规则；
- 整托仍只是收费分类，不恢复库存托盘实体；
- 已生成费用需要修正时通过冲正记录处理，不直接覆盖原记录。

## 15. 取消与平台状态变化

### 15.1 货主主动取消

- `WAITING_SHELF` 可以取消并释放全部预占；
- 从 `PLATFORM_PROCESSING` 开始禁止货主取消；
- 人工订单适用相同边界。

### 15.2 平台取消

- 待下架期间平台取消：自动取消履约并释放预占；
- 仓库接单后但尚未开始拣货：自动取消并释放预占；
- 已开始拣货但尚未签出：进入 `CANCEL_RETURNING`，已拣商品扫码返库后释放；
- 已签出后平台取消：不自动恢复库存，后续进入退货入库流程。

## 16. 前端调整

### 16.1 ERP 货主端

- Ozon、Wildberries、Yandex 订单页增加仓库状态和目标海外仓；
- “确认发货”改为仓库提交和预占；
- 待下架显示取消发货，仓库接单后按钮禁用；
- 删除平台面单打印入口；
- 删除销售出库单菜单和表单；
- 原自定义出库菜单改为人工出库订单。

### 16.2 海外仓平台端

- “下架拣货”改为“订单下架”；
- 按订单显示单个或批量下架结果；
- “下架拣货”和“打包签出”执行页面合并为“取货签出”；
- 删除分货格相关页面、按钮和状态；
- 保留操作员、错误原因、重试和审计信息。

## 17. 后端模块边界

建议新增：

- `FulfillmentOrderService`：履约订单、商品快照和状态 CAS；
- `FulfillmentReservationService`：逻辑库位预占、释放和签出扣减；
- `PlatformFulfillmentOrchestrator`：按阶段协调平台适配器；
- `OzonFulfillmentAdapter`、`WbFulfillmentAdapter`、`YandexFulfillmentAdapter`；
- `FulfillmentPickingService`：任务和逐订单扫描；
- `FulfillmentPackingService`：面单、复核和打包；
- `FulfillmentShippingService`：逐单签出、库存和费用。

现有平台 API 客户端和标签策略继续复用。现有确认服务拆分为适配器阶段动作，不能再由 ERP 订单控制器直接执行完整确认流程。

## 18. 数据切换

保留：

- 用户、角色、菜单基础配置；
- 货主和 WMS 服务商；
- 店铺和平台凭证；
- ERP SKU、内部 SKU 和 SKU 映射；
- 平台订单原始数据及平台状态；
- 仓库、排、逻辑库位、合同和费率。

清理并重新建账：

- 销售出库单和旧自定义出库单；
- 旧物理批次预占和库存；
- 旧拣货任务、分货格占用和包裹；
- 测试签出记录及其测试费用；
- ERP 订单旧 `outbound_order_id` 关联。

旧表在切换前备份。第一阶段停止读写并保留只读核对，验收新流程后再删除。

## 19. 实施顺序

1. 提交当前工作区基线并备份数据库；
2. 完成逻辑库位库存内核；
3. 新增履约订单、商品、预占和平台动作表；
4. 实现 ERP 提交和人工订单；
5. 实现海外仓订单下架和平台分阶段适配；
6. 改造拣货任务为订单级关系；
7. 实现统一取货签出页面；
8. 接入面单、打包、签出、库存流水和计费；
9. 清理测试业务数据并重新建账；
10. 完成回归测试后停止旧接口和菜单；
11. 验收后删除旧销售出库相关表。

## 20. 验收标准

- 同一平台订单不能生成两个有效履约订单；
- 并发确认不会重复预占；
- 库存不足不产生半张任务；
- 待下架取消完整释放预占；
- 批量下架部分失败不影响成功订单；
- 一个履约订单始终对应一个物理包裹；
- 同仓同货主订单可以创建跨平台批量拣货任务；
- 任务按订单逐单作业，不使用分货格；
- 多 SKU、多库位订单能够准确扫码拣货；
- 未拣齐不能打印最终面单或打包；
- 未复核面单不能签出；
- 平台取消能够按仓库进度释放或返库；
- 签出只扣减一次库存并只生成一次费用；
- 平台状态同步不覆盖仓库履约状态；
- 人工订单不调用平台接口；
- Ozon、Wildberries 和 Yandex 按各自阶段调用接口；
- 平台成功、本地失败可以补账且不重复调用平台。

## 21. 非本期范围

- 一个订单拆分多个物理包裹；
- 多个订单合并一个包裹；
- 固定分货格和二次分货；
- 跨货主混合拣货任务；
- 自动规划仓库人员行走路线；
- 平台最后一公里物流追踪功能。
