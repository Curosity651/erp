# 逻辑库位与无批次库存改造设计

日期：2026-08-15  
版本：方案基线 v1.2
状态：当前方案已确认并完成自审，持续补充细节，完成后再进入实施计划

## 1. 改造目标

将现有“二维库位 -> 层位/托位 -> 托盘 -> 批次库存”的复杂模型简化为：

```text
仓库 -> 货架排/公共区域 -> 逻辑库位 -> 库位库存 -> 库存流水
```

所有库位只作为系统中的逻辑位置。现场是否位于货架、地面或仓库角落，不再由系统建立不同的数据结构。

## 2. 已确认的库位结构

### 2.1 仓库与排

- 仓库只维护货架排数，不再维护每排列数、层数和每层托位数。
- 系统按排数自动生成排号，例如 `A1`、`A2`、`A3`。
- 货架分配和服务合同继续以“排”为单位。
- 某一排分配给 WMS 服务商后，该排下的逻辑库位继承其使用权限。
- 未分配的排不能用于正式上架，但平台管理员可以维护其库位。

### 2.2 公共区域

- 每个仓库可维护不参与货架合同计费的公共区域。
- 暂存区库位位于公共区域，可以被所有 WMS 服务商使用，不受按排分配规则限制。
- 公共区域只是权限和计费属性，不建立另一套“虚拟库位”数据结构。

### 2.3 逻辑库位

- 工作人员进入某一排或公共区域后，人工新增逻辑库位。
- 库位编码由系统自动生成，例如 `A1-001`、`A1-002`、`TEMP-001`。
- 库位编码创建后不可修改，库位名称可以修改。
- 支持复制上一个库位和批量新增相同规格的库位，但不再批量生成几何网格。
- 逻辑库位维护以下信息：
  - 仓库、排号或公共区域；
  - 库位编码、库位名称；
  - 库位类型；
  - 内部可用长、宽、高；
  - 自动计算的最大体积；
  - 最大承重；
  - 最大 SKU 种类数，可设置不限；
  - 是否公共库位；
  - 启用或停用状态；
  - 排序号、版本号和操作审计字段。

### 2.4 库位类型

- `STANDARD` 标准区：存放良品，可预占、拣货和出库。
- `RETURN` 退货区：存放退货质检合格商品，可预占、拣货和出库，也可移入标准区。
- `DEFECTIVE` 不良品区：只存放不良品，不可出库、不可移库，只能通过报废流程减少。
- `TEMP` 暂存区：公共位置中的正常库存，可直接预占、拣货和出库，不要求先移入标准区。

现有 `is_virtual` 公共暂存模型退出主流程。所有库位统一采用逻辑库位模型。

## 3. 已确认的库位库存模型

### 3.1 库存聚合维度

库存按以下维度合并：

```text
WMS服务商 + 货主 + 仓库 + 逻辑库位 + 内部SKU + 品质
```

同一维度的重复入库、退货、移入或盘盈直接增加数量，不再产生新的库存批次。

库存字段保留：

- 现存数量；
- 预占数量；
- 乐观锁版本号；
- 创建与更新时间。

库存字段不再包含：

- 入库明细 ID；
- 批次号；
- 入库批次顺序；
- 托盘 ID；
- 托位 ID。

入库、退货、盘点、移库、报废、预占和出库来源全部通过业务单据与库存流水追踪。

### 3.2 混放规则

- 允许同一逻辑库位存放多个货主和多个 SKU。
- 库存通过货主、WMS 服务商和内部 SKU 保持归属隔离。
- 上架推荐顺序为：同货主同 SKU、同货主混放、跨货主混放。
- 最终是否可放入由装箱算法、承重和最大 SKU 种类数共同决定。

## 4. SKU 包装数据

- ERP 货主端创建 SKU 时，完成包装后的外箱长、宽、高和单箱毛重必须填写。
- 一箱按一件处理。
- SKU 还必须维护摆放方向：
  - `ALL` 可任意旋转；
  - `HORIZONTAL_ONLY` 仅允许保持正面朝上并水平旋转；
  - `FIXED` 禁止旋转。
- 默认摆放方向为 `HORIZONTAL_ONLY`。
- 前后端都必须校验必填、正数和单位合法性。
- 历史缺少包装数据的 SKU 可以查看，但补齐前不能用于创建新的入库单。

## 5. 三维装箱与容量校验

后端新增统一的逻辑库位装箱服务。输入目标库位和货物组合，输出：

- 是否可以装入；
- 预计空间利用率；
- 预计重量与承重利用率；
- 剩余体积和剩余承重；
- 失败原因；
- 可选的模拟摆放坐标和方向，仅用于预览。

校验规则：

- 上架和移库预览时计算一次；
- 最终提交时锁定目标库位并重新计算；
- 超出长宽高可摆放空间、最大承重或 SKU 种类数时禁止提交；
- 不永久保存每件家具的三维坐标，库存只记录逻辑库位和数量。

当前项目使用 Java 8，第一阶段可封装兼容 Java 8 的三维矩形装箱组件。算法必须通过内部接口隔离，便于未来升级 Java 或替换实现。

## 6. 托盘退出规则

- 上架直接选择目标逻辑库位，不再选择托盘或托位。
- 移库直接选择源库位、货物、数量和目标库位。
- 仓储过程不再使用托盘号、托盘标签、半托、满托和托盘容量。
- 原托盘管理页面改造成“库位库存”页面。
- 原托盘和托位表在数据库备份完成后停止业务写入；清理业务数据后保留空表结构，稳定运行后再下线。

### 6.1 已确认的现场标签

- 每个逻辑库位打印并张贴一张长期使用的库位标签。
- 家具一箱等于一件，每一个外箱必须张贴一张内部 SKU 标签。
- 内部 SKU 标签标识货主和内部 SKU，同一 SKU 的多个外箱使用同一商品编码，不引入库存批次号。
- 上架完成后可打印上架单，用于留档、复核和交接，不张贴在货物上。
- 不再生成或打印货垛码、托盘码和托位码。

## 7. 已确认的库位调整

库位调整只保留两种操作方式：

- 按商品移库：选择源库位中的货主、SKU、品质和移动数量，再选择目标库位。
- 整库位搬移：一次选择源库位内全部可移动库存，统一移动到一个目标库位。

整库位搬移只是批量选择逻辑库位库存，不再代表整托。

移动规则：

- 良品可以在标准区、退货区和暂存区之间移动。
- 不良品区库存不能移库，只能通过报废流程减少。
- 普通货架排的目标库位必须属于货主对应 WMS 服务商可使用的排。
- 公共暂存区不校验排分配权限。
- 目标库位必须启用，并通过 SKU 种类数、三维装箱和承重校验。
- 移库不改变 WMS 服务商、货主、内部 SKU 和品质。
- 操作员和调整原因必填。
- 已被销售出库预占的数量禁止人工移库，只允许移动可用数量。
- 源库位存在任何预占库存时，禁止整库位搬移。

调整单状态简化为：

```text
PENDING 待调整 -> COMPLETED 已完成
               -> CANCELLED 已取消
```

完成调整时，后端锁定调整单、源库位、目标库位和库存行，重新检查可用数量并运行装箱算法，然后在同一事务中扣减源库存、合并目标库存、写库存流水并 CAS 完成调整单。

暂存区库存允许直接拣货，因此销售出库不再生成“先移入标准区”的待完善库位调整计划。

## 8. 已确认的盘点、退货质检与报废

### 8.1 盘点

- 全仓盘点按排号和库位编码生成全部逻辑库位任务，包含公共暂存区。
- 循环盘点选择部分排或库位。
- 专项盘点按货主、内部 SKU、库位类型或异常条件筛选库位。
- 操作流程为扫描库位、扫描内部 SKU 标签、累计实盘数量、完成当前库位。
- 快照维度为货主、内部 SKU、品质、账面数量和预占数量。
- 账面存在但现场为零时允许填写零。
- 现场发现账外商品时，只能选择已登记且包装数据完整的内部 SKU。
- 盘盈增加库位库存，盘亏减少库位库存，不再产生库存批次。
- 盘点记录操作员、审核人、差异原因和确认时间。
- 盘盈后重新执行装箱计算。现场实际数量导致容量超限时仍按真实数量入账，同时将库位标记为容量异常并要求后续整理。
- 实盘数量小于已预占数量时，盘点单进入“预占冲突”状态，列出受影响的销售出库单。相关预占被取消或调整到不超过实盘数量后，才能最终确认盘亏。

### 8.2 退货质检

- 退货质检完成后直接上架。
- 合格商品可以进入退货区或标准区。
- 不合格商品只能进入不良品区。
- 目标库位必须通过装箱和承重校验。
- 库存直接增加到对应逻辑库位，不创建托盘、托位或批次。
- 缺少内部 SKU 标签时，可从质检结果补打每箱 SKU 标签。
- 质检记录保留照片、说明、操作员和审核信息。

### 8.3 报废

- 报废只能处理不良品区库存。
- 选择货主、不良品库位、内部 SKU 和数量，填写原因并上传凭证。
- 审批通过并确认报废后扣减库位库存并写报废流水。
- 报废流程不再选择批次、托盘或托位。

## 9. 已确认的销售出库预占与拣货

### 9.1 库位库存预占

- 销售出库只查询标准区、退货区和暂存区的良品库存。
- 可用数量为现存数量减已预占数量。
- 预占记录直接关联库位库存 ID，不再关联批次、托盘或托位。
- 预占时使用行锁和条件更新，防止并发超量预占。
- 取消出库时释放预占；拣货完成时同时扣减现存数量和预占数量。
- 暂存区库存可以直接参与预占和拣货。
- 不良品区和正在盘点锁定的库位不参与新预占。
- 出库单自己的预占在再次校验时仍视为该单可用，避免误判缺货。

### 9.2 库位选择策略

取消 FIFO，采用“少跑库位优先”：

1. 优先选择一个库位即可满足全部需求的库存。
2. 单一库位不足时，优先选择库存量较大的库位，尽量减少需要访问的库位数。
3. 所需库位数量相同时，按排号和库位编码自然顺序排列。
4. 暂存区与普通库位都可参与；普通库位可以单独满足时优先普通库位。
5. 平台管理员创建拣货任务时可以更换推荐库位。

### 9.3 拣货操作

- 拣货单显示库位、库位类型、内部 SKU、商品名称和应拣数量。
- 不再显示批次号、入库日期、托盘号和托位。
- 工作人员依次扫描库位码和每箱内部 SKU 标签，每扫描一个外箱累计一件。
- 允许有权限的人员扫码一次后人工填写数量，并记录操作日志。
- 错误库位或错误 SKU 立即提示。
- 实际不足时进入拣货异常，可以重新分配到其他有库存的逻辑库位。
- 预占数量禁止人工移库；有预占的库位只能移动未预占部分。

## 10. 已确认的打包签出与出库收费

整托仅保留为出库收费类型，不再对应库存中的托盘实体：

- 默认按散件或箱数计费；
- 签出时工作人员可选择“按整托出库”并填写整托数量；
- 系统按整托费率计费；
- 记录操作人、整托数量和备注；
- 不通过托盘 ID 判断是否整托。

一个销售出库单可以包含多个平台订单，每个平台订单作为一个物理包裹。逐个包裹完成打包和面单粘贴后，在最后一个包裹签出前统一确认整个销售出库单的出库计费。

计费确认字段：

- 实际出库总件数；
- 整托数量；
- 整托包含箱数；
- 大箱散件数；
- 小件散货数；
- 备注、操作员和确认时间。

数量必须满足：

```text
整托包含箱数 + 大箱散件数 + 小件散货数 = 实际出库总件数
```

“整托包含箱数”只用于数量守恒校验，不参与计费。费用为整托数量乘整托单价，加大箱散件数乘大箱单价，加小件散货数乘小件单价。

同一销售出库单通过数据库幂等键只生成一次费用。已产生费用后不能直接修改，确需修正时通过费用冲正记录处理并保留原始凭证。

## 11. 已确认的技术路线

采用新增库位库存内核的切换方式，该路线已经确认：

1. 新增逻辑库位字段和库位库存表。
2. 备份数据库后清理仓库业务数据，不迁移旧托盘、托位和批次库存。
3. 切换上架、移库、盘点、退货、报废、预占、拣货、出库和收费到新库存内核。
4. 旧托盘、托位和批次表停止业务写入，旧接口和菜单隐藏或禁用。
5. 通过新入库、盘点初始化或受控库存初始化重新建账。
6. 新链路稳定运行并完成回归验证后，再删除旧接口和表结构。

不采用只隐藏前端或直接复用旧批次表的方案，避免旧托盘、托位和批次语义继续污染新业务。

### 11.1 已确认的数据切换方式

采用清理仓库业务数据后重新建账，不迁移旧托盘、托位和批次库存。

保留：

- 用户、角色、菜单和权限；
- WMS 服务商、ERP 货主和店铺；
- SKU 主数据、内部 SKU 编码和 SKU 映射；
- 仓库基础资料；
- 货架排分配；
- 服务合同、合同资金配置和收费费率。

清理：

- 入库、收货、上架及其明细；
- 旧库存、托盘、托位和托盘操作日志；
- 库位调整、盘点、退货质检、报废；
- 销售出库、预占、拣货、分货、打包和签出测试数据；
- 由上述测试业务产生的库存流水、收费记录和应收账单。

清理前必须创建数据库备份和 Git 基线。新模型发布后重新创建逻辑库位，并通过新的入库、盘点初始化或受控库存初始化功能重新建账。

## 12. 已确认的前端信息架构

仓库管理菜单使用：

- `库位设置`：替代原库位管理，维护仓库排、公共区域和逻辑库位。
- `货架分配`：继续按排分配 WMS 服务商并关联合同。
- `库位库存`：替代原托盘管理，按逻辑库位查看货主、SKU、数量、预占和容量。

库位设置页面不再展示几何网格、层数、每层托位、托盘规则和托位标签。选择排或公共区域后，以列表方式新增、复制、批量新增、编辑、停用和打印逻辑库位标签。

库位库存页面按仓库、排、库位、库位类型、WMS 服务商、货主、内部 SKU、状态和容量状态筛选。列表展示总件数、可用与预占、空间利用率和承重利用率；详情展示库存组成、装箱结果和库存流水。

## 13. 实施顺序

### 13.1 数据库与基础模型

- 新增逻辑库位规格、状态、公共属性和版本字段。
- 新增 `wms_location_inventory`，唯一维度为 WMS 服务商、货主、仓库、库位、内部 SKU 和品质。
- 新增 SKU 摆放方向和出库计费确认数据。
- 增加数量非负、预占不超过现存、库位编码唯一和计费幂等约束。

### 13.2 库存内核

- 建立库位库存、预占、库存流水和三维装箱统一服务。
- 列表页使用缓存的体积与重量利用率；上架、移库和库位容量修改时运行完整装箱校验。
- 所有库存写入统一经过新内核，不允许业务模块直接更新数量。

### 13.3 业务切换

按以下顺序切换：

1. ERP SKU 包装数据校验。
2. 库位设置与库位库存。
3. 入库收货与上架。
4. 库位调整。
5. 盘点。
6. 退货质检与报废。
7. 销售出库预占与拣货。
8. 打包签出与出库收费。
9. 库存总览、资产和统计读取新库存。

### 13.4 数据切换

1. 停止业务写入。
2. 创建数据库备份和 Git 基线。
3. 部署新表、新字段和新代码。
4. 清理仓库测试业务及其派生收费数据。
5. 创建逻辑库位并补齐保留 SKU 的包装数据。
6. 通过新业务重新建账。
7. 校验货主归属、数量、预占、流水和费用。
8. 启动前后端并执行普通业务回归。

## 14. 验收范围

- 多货主、多 SKU 在同一逻辑库位混放且归属不串。
- SKU 三种旋转规则、三维装箱失败原因和承重限制生效。
- 并发上架、并发预占、并发移库不会超量或超容量。
- 暂存区可以直接预占、拣货和出库。
- 预占库存不能人工移库。
- 盘点实盘低于预占时进入预占冲突，不能形成非法库存。
- 退货良品和不良品进入正确库位类型，不良品只能报废。
- 出库采用少跑库位优先，并支持人工更换推荐库位。
- 扫描库位码和每箱内部 SKU 标签可以准确完成拣货。
- 最后一个包裹签出时只生成一次出库费用，数量守恒且重复提交幂等。
- FBO 库存快照、电商平台订单同步和店铺数据不受本次仓内库存清理影响。
- 前后端编译、数据库约束测试和普通业务回归全部通过。

## 15. 后续增补

本文件作为持续更新的方案基线。后续确认的业务逻辑和界面细节继续追加到本文档；在全部细节确认前不开始业务代码实施。

### 15.1 按排动态增删逻辑库位

- 仓库先确定排数，逻辑库位数量不属于固定仓库几何结构。
- 进入某一排后，填写本次新增库位数量，并选择一套默认规格批量创建。
- 默认规格包含库位类型、名称前缀、内部长宽高、最大承重、最大 SKU 种类数和启用状态。
- 批量生成后允许逐个修改库位名称、规格和适用属性。
- 每一排可以随时增加新的逻辑库位，不需要重新生成仓库结构。
- 删除库位前必须满足库存数量为零、预占数量为零，并且没有未完成的上架、移库、盘点或出库任务引用。
- 已产生历史流水的库位采用逻辑删除，历史业务单据继续显示原库位编码。
- 删除库位不会重排其他库位编码，也不会重复使用已经分配过的编码。
- 空库位可以修改规格和类型；有货库位修改尺寸或承重时必须重新执行装箱校验，新规格无法容纳现有货物时禁止保存。
- 有货库位不能修改所属排、库位编码或库位类型；需要调整时必须先清空库存并解除业务占用。

### 15.2 库位库存双视图

原托盘管理改成库位库存后，提供网格视图和树形列表视图，两种视图使用同一份筛选条件和汇总数据。

#### 网格视图

- 按排分组展示该排全部逻辑库位，公共暂存区作为独立分组。
- 每个库位使用稳定尺寸的方块展示，方块中的填充高度类似电池电量，表示体积使用率。
- 方块同时显示库位编码、库位类型、体积使用百分比、实际已用体积、库位总体积、总件数和 SKU 种类数。
- 空库位使用灰色；正常、较高、接近满载和已满使用不同状态色；装箱算法判断剩余空间不可利用时显示“布局受限”；超过理论容量时显示“容量异常”。
- 点击库位方块打开统一的库位库存详情抽屉。

#### 树形列表视图

- 使用“排 -> 逻辑库位”两层树形表格，点击排号展开所属库位。
- 排级别显示库位数量、总体积、已用体积、体积使用率和异常数量汇总。
- 库位级别显示编码、名称、类型、所属服务商或公共区域、货主数、SKU 种类数、总件数、可用与预占、体积、重量和状态。
- 分页以排为单位，不能将同一排的库位拆分到不同页面。
- 排号、库位编码均采用自然顺序排序。

#### 库位详情

- 基本信息：仓库、排、编码、名称、类型、长宽高、总体积、最大承重和状态。
- 容量信息：商品外箱总体积、体积使用率、当前总重量、承重使用率、剩余体积、剩余承重和最近一次装箱结果。
- 货物明细：WMS 服务商、货主、内部 SKU、商品名称、品质、现存、预占、可用和占用体积。
- 最近流水：入库、移库、盘点、预占、释放、出库和报废。

#### 体积与承重显示

- 主电池只表示体积使用率，并显示实际已用体积和库位总体积。
- 承重使用率使用单独的小型进度条。
- 不将体积和承重合并为一个百分比。
- 任一指标接近或达到上限时，库位状态都必须给出对应警告。例如体积使用 60% 但承重使用 95% 时，主电池显示 60%，承重条显示红色，并将状态标记为接近承重上限。

#### 查询性能

- 上架、移库、盘点和出库完成后事务内更新库位容量汇总。
- 网格和列表一次查询汇总值，不逐个库位运行三维装箱算法。
- 点击详情时再加载货物明细、流水和完整装箱结果。
- 网格与列表切换时复用同一份最新数据，不重复请求。
- 业务操作完成后自动刷新，同时保留手动刷新按钮。
