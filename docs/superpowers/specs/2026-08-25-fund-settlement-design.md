# 资金结算与充值记录功能设计

## 一、目标

在不接入真实支付、不控制银行账户的前提下，为系统增加两条可审计的预存资金记录链路：

1. ERP 货主向所属 WMS 服务商充值，用于记录物流产品费用。
2. WMS 服务商向海外仓平台充值，用于记录入库、出库、仓储等平台服务费用。

系统展示充值、费用、记录余额和凭证。余额不足只预警，不阻止订单、入库、上架、出库或签出。

## 二、核心业务口径

### 2.1 两类账户关系

| 账户范围 | 付款方 | 收款方 | 消费来源 |
| --- | --- | --- | --- |
| 货主账户 | ERP 货主 | 所属 WMS 服务商 | `wms_client_billing_record` 物流产品费用 |
| 平台账户 | WMS 服务商 | 海外仓平台 | `wms_billing_record` 平台仓储服务费用 |

合同押金、认购款和一次性货架租赁费继续走合同资金流水，不计入平台充值余额，也不与月度服务费用重复扣减。

### 2.2 余额计算

不建立可人工修改的余额字段，余额由已确认充值和既有费用流水实时汇总：

```text
货主记录余额 = WMS 已确认的货主充值 - 已产生的物流产品费用
平台记录余额 = 平台已确认的服务商充值 - 已产生的平台仓储服务费用
```

规则：

- CNY、RUB 等币种分别核算，不进行汇率折算。
- 待审核、已驳回、已取消充值不计入余额。
- 月度账单只是平台费用的汇总快照，不能再次扣减余额。
- 余额允许小于零，负余额用红色显示并产生预警，不影响业务执行。

## 三、充值流程

### 3.1 ERP 货主向 WMS 服务商充值

1. ERP 货主进入资产与账务中的 WMS 账户区域。
2. 填写金额、币种、实际付款时间和备注，上传付款凭证。
3. 系统生成充值单，状态为 `PENDING`。
4. 所属 WMS 服务商在资金结算的“货主结算/充值审核”中查看凭证。
5. WMS 服务商选择通过或驳回；驳回必须填写原因。
6. 审核通过后充值计入该货主、该服务商、该币种的记录余额。

### 3.2 WMS 服务商向海外仓平台充值

1. WMS 服务商进入资金结算的“平台结算”。
2. 登记金额、币种、实际付款时间和备注，上传付款凭证。
3. 系统生成充值单，状态为 `PENDING`。
4. 海外仓平台在“平台财务/服务商资金”中审核。
5. 审核通过后充值计入该服务商、该币种的平台账户余额。

### 3.3 状态与修正

```text
PENDING -> APPROVED
        -> REJECTED
        -> CANCELLED（仅提交人可在审核前取消）

APPROVED -> REVERSED（审核方冲正，必须填写原因）
```

- 已通过记录不可编辑、不可物理删除。
- 错误的已通过记录通过冲正处理，冲正记录引用原充值单并保留操作人、时间和原因。
- 审核、取消、冲正均采用状态条件更新，防止重复点击或多人并发处理。

## 四、数据设计

新增 `wms_recharge_order`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `recharge_no` | 充值单号，全局唯一 |
| `account_scope` | `OWNER_ACCOUNT` / `PLATFORM_ACCOUNT` |
| `wms_tenant_id` | WMS 服务商 |
| `erp_tenant_id` | ERP 货主；平台账户为空 |
| `amount` | 充值金额，必须大于零 |
| `currency` | 币种快照 |
| `payment_time` | 实际付款时间 |
| `voucher_file_id` | 付款凭证文件，必填 |
| `status` | `PENDING/APPROVED/REJECTED/CANCELLED/REVERSED` |
| `applicant_id/name` | 提交人快照 |
| `reviewer_id/name` | 审核人快照 |
| `review_time` | 审核时间 |
| `reject_reason` | 驳回原因 |
| `reverse_order_id` | 冲正关联的原充值单 |
| `reverse_reason` | 冲正原因 |
| `remark` | 备注 |
| `create_time/update_time` | 审计时间 |

约束与索引：

- `recharge_no` 唯一。
- `amount > 0` 由后端和数据库共同校验。
- `OWNER_ACCOUNT` 必须有 `erp_tenant_id`；`PLATFORM_ACCOUNT` 不允许传货主。
- 按 `(account_scope, wms_tenant_id, erp_tenant_id, currency, status, create_time)` 建查询索引。
- 凭证文件必须存在且属于当前业务可访问范围。

不复制既有消费费用到新表，避免双写和重复扣减。账户详情通过充值表与现有费用表形成统一只读流水。

## 五、权限与数据隔离

### ERP 货主

- 只能查看自己与当前所属 WMS 服务商之间的账户。
- 只能提交自己的充值、查看自己的凭证和流水。
- 只能取消自己尚未审核的充值。
- 无权审核或冲正。

### WMS 服务商

- 只能查看和审核分配给自己的货主充值。
- 可查看名下货主的物流产品费用和记录余额。
- 只能为自己登记平台充值。
- 无权审核自己的平台充值。

### 海外仓平台

- 可查看全部 WMS 服务商的平台账户。
- 只能审核、驳回或冲正 WMS 服务商向平台提交的充值。
- 不直接修改任何账户余额。

## 六、前端信息架构

### 6.1 ERP 货主端

在现有“资产与账务”页面增加 `WMS账户` 区域，不额外增加大量菜单：

- 当前所属 WMS 服务商。
- 分币种记录余额。
- 累计充值、物流产品费用、待审核充值。
- `充值登记`按钮。
- 充值记录与物流费用流水。

### 6.2 WMS 服务商端

将原“财务收入”和“财务支出”合并并更名为：

```text
服务商运营 -> 资金结算
```

页面包含两个主选项卡：

#### 货主结算

- 顶部卡片：货主账户总余额、本月已确认充值、本月物流产品费用、待审核笔数。
- 账户总览：按货主和币种展示累计充值、累计费用、余额和最近变动。
- 充值审核：查看凭证并通过或驳回。
- 物流费用流水：复用现有财务收入数据。

#### 平台结算

- 顶部卡片：平台账户余额、累计充值、累计平台费用、本月待出账费用。
- 平台账户：按币种展示充值、费用和余额。
- 充值记录：登记充值、查看凭证和审核结果。
- 服务账单：复用现有财务支出/月度账单数据。

### 6.3 海外仓平台端

在“平台财务”下增加 `服务商资金`：

- 按 WMS 服务商和币种展示累计充值、平台服务费用和余额。
- 展示待审核充值数量。
- 支持查看凭证、审核、驳回和冲正。
- 支持按服务商、币种、状态、日期筛选。

## 七、后端接口边界

建议统一使用 `/fund-settlement` 领域接口，不让前端自行拼接余额：

- ERP：账户概览、充值分页、提交、取消、统一流水。
- WMS：货主账户概览、货主充值审核、平台账户概览、平台充值提交、服务账单。
- 平台：服务商账户概览、平台充值审核、冲正、统一流水。

所有账户概览和统一流水由后端完成租户过滤、币种分组和费用汇总。

## 八、错误处理

- 未上传凭证、金额小于等于零、币种为空：拒绝提交。
- ERP 与 WMS 不存在有效所属关系：拒绝提交货主充值。
- 非当前收款方审核：返回 403。
- 状态已变化：返回 409 并要求刷新。
- 凭证文件不存在或不可访问：拒绝提交或审核。
- 余额为负：返回正常业务结果并携带预警标志，不抛业务异常。

## 九、迁移与兼容

- 新增数据库迁移 `V132__fund_settlement_recharge.sql`。
- 保留现有 `wms_client_billing_record`、`wms_billing_record` 和 `wms_monthly_bill`。
- 原“财务收入”和“财务支出”菜单迁移为一个“资金结算”菜单，旧路由可暂时重定向到新页面，避免已打开标签失效。
- 不对历史费用生成虚构充值，初始余额允许为负数。
- 不修改合同资金和应收账单现有历史数据。

## 十、验证标准

1. ERP 上传凭证后，WMS 能看到同一待审核充值；其他服务商不可见。
2. WMS 审核通过后，双方余额增加且重复审核不重复入账。
3. WMS 上传平台充值后，只有平台可审核。
4. 两类余额均按币种独立计算，月度账单不会造成重复扣减。
5. 余额为负时页面预警，但订单和仓库作业仍可继续。
6. 已通过充值不能编辑或删除，冲正后余额恢复并保留完整审计记录。
7. 旧财务收入、财务支出数据在资金结算新页面完整可见。
8. 页面、API 和 SQL 均通过租户隔离、并发状态和凭证权限测试。
