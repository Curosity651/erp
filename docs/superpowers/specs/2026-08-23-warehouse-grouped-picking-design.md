# 独立拣货任务与逐单作业设计

## 目标

将“拣货任务”从“出库作业”中拆分为独立二级菜单，形成清晰链路：

```text
订单下架 → 拣货任务 → 出库作业
```

- 订单下架负责平台确认，并按仓库自动生成任务。
- 拣货任务负责领取、逐单取货、打印并核验面单、完成打包。
- 出库作业只负责已打包包裹的单个或批量签出。

保留现有履约订单、库存预占、任务表头、任务订单和任务明细模型，不重新引入销售出库单或包装单。

## 已确认规则

### 任务生成

- 订单下架只允许勾选 `WAITING_SHELF` 订单。
- 后端逐单执行平台确认；成功订单转为待拣货，失败订单保持原状态。
- 成功订单仅按 `warehouseId` 分组，每个仓库生成一张新任务。
- 不按货主、WMS 服务商、店铺、平台或物流产品拆分。
- 同一仓库的不同货主、服务商及平台订单允许进入同一任务。
- 每次确认都创建新任务，不向已有任务追加订单。

### 任务领取

- 新任务为“待领取”，不绑定执行下架操作的人。
- 一张任务同一时刻只能由一名拣货员领取。
- 领取采用数据库条件更新；成功后记录拣货员、领取时间并进入“拣货中”。
- 其他员工可以查看，但不能扫描、打包或完成任务。
- 当前拣货员可释放任务；管理员可转交任务。释放或转交不清除已有进度。

### 任务内订单

- 任务详情以订单列表展示全部订单，默认按取货库位自然顺序排列。
- 拣货员可以选择任意待处理订单，但界面同一时刻只激活一张。
- 切换订单时保留已提交的扫描进度。
- 不支持多人共同操作一张任务。

### 单订单完成条件

每张订单必须连续完成：

1. 查看取货库位、内部 SKU 和应取数量。
2. 扫描库位码。
3. 扫描箱上的内部 SKU 条形码并记录取货数量。
4. 所有商品取齐。
5. 获取并打印平台面单。
6. 扫描已粘贴面单条码进行核验。
7. 填写或确认承运商、运输方式、跟踪号和包裹重量。
8. 确认打包完成。

商品仅取齐时进入“待贴面单”，不能视为完成或进入出库作业。全部完成后，包裹进入出库作业等待签出。

### 异常处理

- 缺货、货损、条码不符或面单生成失败时可标记异常。
- 必须选择异常类型并填写说明，允许上传现场照片。
- 异常订单不阻塞任务内其他订单。
- 异常期间保留库存预占。
- 管理员可“恢复拣货”或“取消订单”。
- 恢复后回到异常前阶段并保留有效进度；尚未取货的异常订单取消时直接释放预占，已经取货的订单进入取消回退，扫码放回后再释放预占并同步 ERP 内部状态。
- 存在未处理异常时任务显示“部分异常”，不能标记为全部完成。

## 状态设计

### 任务状态

```text
待领取 PENDING
    ↓ 领取
拣货中 PICKING
    ├─ 全部有效订单完成 → 已完成 COMPLETED
    ├─ 存在未处理异常 → 部分异常 PARTIAL_EXCEPTION
    └─ 无有效订单并取消 → 已取消 CANCELLED
```

异常处理完成且仍有订单待操作时，任务恢复为 `PICKING`。

### 任务订单状态

```text
待处理 PENDING
    ↓ 首次有效扫描
处理中 PICKING
    ↓ 商品取齐
待贴面单 WAITING_LABEL
    ↓ 面单核验并完成打包
已完成 COMPLETED

任一未完成状态 ──标记异常──→ EXCEPTION
EXCEPTION ──恢复──→ 异常前阶段
EXCEPTION ──取消──→ CANCELLED
```

## 页面设计

### 菜单

```text
海外仓作业
├─ 入库收货
├─ 入库上架
├─ 订单下架
├─ 拣货任务
├─ 出库作业
├─ 报废单
├─ 退货质检
└─ 盘点管理
```

新建独立路由和页面并继承原出库作业角色授权。出库作业移除嵌入的任务列表，只保留已打包待签出包裹。

### 任务列表

筛选条件：任务号、仓库、状态、拣货员、创建时间。

列表字段：任务号、仓库、订单/件数、完成进度、异常数、状态、拣货员、领取时间、创建时间、操作。

操作按状态显示“领取任务”“继续作业”“查看”“释放任务”“转交”“打印拣货单”。布局与入库收货一致，筛选项自动换行；表格首列和操作列固定，中间区域内部横向滚动。

### 任务作业页

领取后进入独立页面，不使用抽屉：

- 左侧订单队列展示订单号、平台、货主、首个库位、SKU/件数和状态。
- 可筛选待处理、处理中、待贴面单、已完成和异常订单。
- 右侧只展示当前订单，并按“扫描取货、打印核验面单、完成打包”显示步骤。
- 取货区显示库位、内部 SKU、商品、应取和已取数量。
- 打包区显示平台面单、条码核验、承运商、运输方式、跟踪号和重量。
- 提供“标记异常”和“保存并切换订单”。

打印拣货单以整张任务为范围，按库位自然顺序列出订单、内部 SKU 和数量；系统操作仍逐单扫描和打包。

## 后端与数据

### 任务表头

继续使用 `wms_fulfillment_pick_task`：

- `warehouse_id` 必填。
- `wms_tenant_id`、`erp_tenant_id` 可空，不代表单一归属。
- 保存 `operator_id`、`claimed_time`、`task_status`。
- 领取、释放和转交使用状态条件更新，防止重复领取。

### 任务订单

继续使用 `wms_fulfillment_pick_task_order`：

- 一个履约订单只能关联一张有效任务，保留唯一约束。
- 保存订单状态、处理时间、异常类型、说明、图片和异常前状态。
- 详情接口接受用户选中的履约订单 ID，不再强制处理顺序第一单。

### 拣货明细

继续使用 `wms_fulfillment_pick_task_line`：

- 通过库存预占生成库位、内部 SKU 和计划数量。
- 扫描时校验任务领取人、订单归属、库位、内部 SKU、剩余数量和版本。
- 数量使用条件更新，防止重复提交和超拣。

## 接口调整

- 任务列表增加仓库、状态、拣货员和时间范围查询。
- 增加领取、释放和管理员转交接口。
- 任务详情返回任务汇总、订单队列和每单路线进度。
- 扫描接口不再强制只能处理顺序第一张订单。
- 增加标记异常、恢复异常和取消异常订单接口。
- 完成打包接口更新任务订单，并在全部有效订单完成后更新任务状态。
- 写接口校验当前用户是领取人；转交和异常处置使用独立权限。

## 库存一致性

- 任务生成只固化预占和取货路线，不立即扣减物理库存。
- 扫描只记录进度，不允许超过预占数量。
- 完成打包只固化包裹和任务进度；正式签出时执行现有库存扣减与计费逻辑并保持幂等。
- 异常保留预占；未取货订单取消时释放，已取货订单完成扫码回库后释放。
- 每张订单只允许在正式签出事务中扣减一次库存。
- 订单、任务订单、明细和库存更新位于一致的事务边界。

## 错误处理

- 平台确认失败只影响对应订单。
- 一个仓库任务创建失败不回滚其他仓库；成功下架但派单失败的订单保持待拣货并返回原因。
- 领取冲突提示任务已被他人领取并刷新列表。
- 库位、内部 SKU 或数量不匹配时不改变进度。
- 面单失败保留取货进度，允许重试或标记异常。
- 重复提交由状态条件、版本号和唯一约束保证幂等。

## 迁移兼容

- 新菜单继承原出库作业可见角色。
- 历史 `PICKING` 任务保留操作员并视为已领取。
- 历史 `COMPLETED` 任务保持完成。
- 新任务使用 `PENDING`，不重置历史进度。
- 新页面稳定后再清理无调用旧接口。

## 验证

### 后端

- 同仓库跨货主订单生成一张任务，不同仓库生成多张。
- 两名员工同时领取时只有一人成功。
- 非领取人不能扫描、打包或释放。
- 任意选择订单可正常扫描，切换不丢进度。
- 库位、内部 SKU 或数量不匹配时拒绝更新。
- 商品取齐但面单未核验时不能完成。
- 异常不阻塞其他订单，恢复保留原阶段和进度。
- 异常取消释放预占，任务状态正确重算。
- 全部有效订单完成后任务只完成一次。

### 前端

- 菜单权限、筛选、领取和继续作业入口正确。
- 订单可以任选，但界面始终只激活一单。
- 各步骤按钮随状态正确启用或禁用。
- 异常、网络失败和刷新恢复提示明确。
- 出库作业只显示已打包待签出的包裹。
- 页面不产生整页横向滚动，表格内部可滚动。

## 实施边界

本轮不实现多人共同拣一张任务、按货主拆任务、机器人拣货、PDA 离线模式、自动路径优化和复杂绩效计费。任务只按仓库分组，订单默认按库位排序，人工选择并逐单完成。
