# 物流产品与订单级取货签出改造设计

状态：业务方案已确认，等待书面规格审阅后进入实施计划。

## 1. 改造目标

本次改造在现有订单级仓库履约内核上，引入轻量物流产品，并将海外仓取货、面单、打包和签出整理为符合现场操作的逐单流程。

核心目标：

- 一张平台订单或人工订单对应一个履约订单和一个物理包裹；
- 下架支持一次处理多个订单；
- 拣货任务可以包含多个订单，但任务内严格逐单操作；
- 当前订单取齐后立即打印、复核并粘贴面单，不等待其他订单取完；
- 当前订单打包完成后再处理下一张订单；
- 已打包订单支持批量签出；
- 不使用分货格，不进行集中取货后的二次分货；
- 系统只记录实际物流信息，不对签出后的运输状态进行跟踪；
- 物流产品收入归 WMS 服务商，仓库出库作业收入归海外仓平台。

## 2. 系统角色与职责

### 2.1 ERP 货主

- 查看所属 WMS 服务商启用中的物流产品；
- 为店铺设置默认物流产品；
- 确认发货时使用默认产品或临时改选其他产品；
- 查看订单物流产品、实际物流信息和相关费用；
- 待下架期间可以取消仓库履约。

### 2.2 WMS 服务商

- 创建、修改、启用和停用自己的物流产品；
- 设置产品默认费用、币种和详细说明；
- 查看所属 ERP 货主使用物流产品产生的收入；
- 在订单签出前调整实际物流产品费用，并记录调整原因；
- 向海外仓平台承担拣货、打包和签出作业费用。

### 2.3 海外仓平台

- 查看全部 WMS 服务商推送到仓库的履约订单；
- 按订单查看物流产品名称、费用快照和产品说明；
- 执行订单下架、取货、面单、打包和签出；
- 填写或确认实际承运商、运输方式、跟踪号和实际重量；
- 不能修改 WMS 服务商向 ERP 货主收取的物流产品费用；
- 获得仓库拣货、打包和签出作业收入。

## 3. 物流产品模型

新增 WMS 服务商级物流产品。产品属于一个 WMS 服务商，该服务商下全部 ERP 货主可以使用，不再增加货主授权表。

建议表名：`wms_logistics_product`。

主要字段：

- `id`；
- `wms_tenant_id`：所属 WMS 服务商；
- `product_code`：服务商范围内唯一编码；
- `product_name`；
- `default_fee`；
- `currency`；
- `description`：运输、包装、面单和操作要求的详细说明；
- `status`：启用或停用；
- `create_by`、`create_time`、`update_by`、`update_time`、`deleted`。

唯一约束：

```text
UNIQUE(wms_tenant_id, product_code, deleted)
```

第一版不建立以下结构化能力：

- 承运商渠道绑定；
- 邮编和派送分区；
- 重量段和体积重；
- 自动比价；
- 物流商轨迹查询；
- 自动选择实际承运商。

这些要求由产品说明表达，实际运输方式由仓库线下安排并在签出时记录。

## 4. 店铺默认物流产品

ERP 店铺增加 `default_logistics_product_id`。

规则：

- 默认产品必须属于店铺货主的父级 WMS 服务商；
- 默认产品必须处于启用状态；
- 确认发货时自动带出店铺默认产品；
- ERP 用户可以针对当前订单临时修改；
- 临时修改不覆盖店铺默认配置；
- 店铺没有默认产品时，确认发货必须人工选择；
- 默认产品被停用后，历史订单不受影响，新订单必须重新选择。

## 5. 履约订单物流产品快照

在 `wms_fulfillment_order` 增加：

- `logistics_product_id`；
- `logistics_product_code_snapshot`；
- `logistics_product_name_snapshot`；
- `logistics_product_description_snapshot`；
- `logistics_default_fee_snapshot`；
- `logistics_actual_fee`；
- `logistics_currency`；
- `logistics_fee_adjust_reason`；
- `logistics_fee_adjust_by`；
- `logistics_fee_adjust_time`。

ERP 提交订单时保存完整快照。物流产品后续改名、停用或调价不得影响历史订单。

费用调整规则：

- 实际费用初始等于默认费用快照；
- 只有履约订单所属 WMS 服务商有权调整；
- 调整值与默认费用不同时必须填写原因；
- 调整只能发生在签出前；
- 已签出费用只能通过冲正或补充费用记录处理，不能直接覆盖原账单。

## 6. ERP 确认发货

ERP 平台订单确认流程：

```text
选择订单
→ 自动带出店铺默认物流产品
→ 允许本单临时更换
→ 选择目标海外仓
→ 校验店铺、仓库权限和服务有效期
→ 校验 SKU 映射、外箱资料和可用库存
→ 创建订单级履约订单和商品快照
→ 保存物流产品与费用快照
→ 按逻辑库位预占库存
→ 进入 WAITING_SHELF
```

任一校验失败时，履约订单、商品快照和库存预占全部回滚。同一来源订单通过来源唯一键保持幂等，不能重复创建履约订单或重复预占。

人工订单同样必须选择物流产品，但没有店铺默认值时由用户人工选择。

## 7. 海外仓订单下架

订单下架页面按履约订单展示：

- 履约单号和平台订单号；
- 平台、货主、店铺；
- 物流产品；
- SKU 种类和件数；
- 目标仓库；
- 当前状态、平台动作阶段和失败原因。

支持单个和批量下架。批量操作逐单执行：

- 平台订单通过现有平台适配器执行下架阶段动作；
- 人工订单跳过平台接口；
- 成功订单从 `WAITING_SHELF` 进入 `WAITING_PICK`；
- 失败订单保留 `WAITING_SHELF`、库存预占和错误原因；
- 一个订单失败不回滚同批次其他成功订单；
- 从下架成功开始，ERP 货主不能主动取消。

这里的“下架”表示仓库接单并执行平台确认，不表示物理商品已经从库位取出。

## 8. 拣货任务

待取货订单可以单个或批量创建拣货任务。

任务约束：

- 所选订单必须属于同一个仓库；
- 所选订单必须属于同一个 ERP 货主；
- 可以混合 Ozon、Wildberries、Yandex 和人工订单；
- 一张订单不能同时属于两个有效拣货任务；
- 一个任务可以包含多个订单，但订单和物理包裹始终一对一；
- 任务内严格按照订单顺序操作，当前订单未完成前不能开始下一单。

拣货单打印内容：

- 任务号和任务条码；
- 订单顺序和订单号；
- 每张订单的库位路线；
- 分区、库位编码、内部 SKU、商品名称和应取数量；
- 物流产品名称和必要说明。

## 9. 取货路线与扫描规则

系统根据订单的逻辑库位库存预占生成取货路线，按照库位编码自然排序。

取货页面同时展示：

- 任务订单列表；
- 当前订单完整路线；
- 当前目标库位及分区；
- 当前库位下的内部 SKU、应取数量和已取数量；
- 下一目标库位。

现场操作：

```text
打开当前订单
→ 系统提示目标库位
→ 工人到达库位并扫描库位标签
→ 系统校验库位与预占一致
→ 逐件扫描内部 SKU 条形码
→ 当前库位数量完成
→ 自动提示下一库位
→ 当前订单所有商品取齐
```

必须拒绝：

- 错误仓库或错误库位；
- 错误货主；
- 不属于当前订单的 SKU；
- 扫描数量超过应取数量；
- 当前订单未完成时操作下一订单；
- 已被其他任务占用或已经完成的订单。

有权限的人工登记需要填写原因并记录操作人和时间。

## 10. 逐单面单与打包

取货与面单属于同一个订单作业循环，不设置“先取完全部订单再集中打单”的阶段。

当前订单最后一件商品扫描完成后：

```text
“打印面单”按钮启用
→ 员工主动点击打印
→ 系统根据订单来源获取面单
→ 扫描面单条码复核
→ 确认面单已粘贴
→ 确认打包
→ 当前订单进入 PACKED
→ 自动打开任务中的下一张订单
```

员工主动点击打印，不能在最后一次商品扫描后自动打印，以避免误扫描或打印机异常造成无意重复打印。

面单来源：

- Ozon 订单调用 Ozon 面单接口；
- Wildberries 订单调用 Wildberries 面单接口；
- Yandex 订单调用 Yandex 面单接口；
- 人工订单生成系统普通发货标签。

物流产品不决定面单接口。系统按照订单来源调用现有平台适配器。

禁止未取齐打印最终面单、未复核面单确认打包、未完成当前订单切换下一订单。

## 11. 批量签出

取货任务中的订单逐单完成打包。任务内全部订单处理完成后，或者已有部分订单处于 `PACKED` 时，仓库可以选择多张已打包订单批量签出。

每张订单签出前必须具备：

- 实际承运商；
- 实际运输方式；
- 跟踪号；
- 实际重量；
- 面单复核记录；
- 打包完成记录。

平台接口或面单结果可以自动带出承运商、运输方式和跟踪号，但仓库人员必须确认；无法自动获取时允许人工填写。跟踪号需要避免与其他有效包裹重复。

批量签出逐单执行：

```text
校验订单已打包和物流信息完整
→ 调用平台最终动作
→ 锁定履约订单和库存预占
→ 扣减现存库存及预占
→ 写库存流水和签出记录
→ 生成物流产品服务费
→ 生成仓库出库操作费
→ 更新为 SHIPPED
```

批量部分失败时：

- 成功订单保持 `SHIPPED`；
- 失败订单保持 `PACKED`；
- 返回每张失败订单的具体原因；
- 修复后只重试失败订单；
- 平台动作、库存扣减和费用生成必须保持幂等。

签出后系统不查询承运商轨迹，也不维护运输中、派送中或已签收状态。ERP 用户只查看并复制承运商、运输方式和跟踪号，自行到对应平台查询。

## 12. 状态模型

仓库履约状态：

```text
WAITING_SHELF   待下架
WAITING_PICK    待取货
PICKING         取货中
WAITING_PACK    当前订单已取齐，待打印、复核面单并完成打包
PACKED          已贴单并打包
SHIPPED         已签出，仓库履约完成
CANCELLED       已取消
EXCEPTION       异常
```

正常状态流：

```text
WAITING_SHELF
→ WAITING_PICK
→ PICKING
→ WAITING_PACK
→ PACKED
→ SHIPPED
```

平台同步状态继续独立保存在 ERP 订单平台状态字段中，不能覆盖仓库内部履约状态。

`WAITING_PACK` 沿用现有履约内核状态，前端在该状态内按“打印面单 → 扫码复核 → 确认已贴单打包”顺序控制操作，不再增加含义重复的状态。

## 13. 费用与账务

每张订单签出成功后生成两类互相独立的费用记录。

### 13.1 物流产品服务费

```text
付款方：ERP 货主
收款方：WMS 服务商
金额：履约订单的实际物流产品费用
```

该费用计入 ERP 货主支出和 WMS 服务商物流产品收入，不计入海外仓平台收入。

### 13.2 仓库出库操作费

```text
付款方：WMS 服务商
收款方：海外仓平台
金额：现有仓库出库收费规则计算结果
```

该费用计入 WMS 服务商仓库作业支出和海外仓平台作业收入。

同一履约订单的同一费用类型只能生成一次。已生成账单的修正通过冲正或补充费用处理。

复用现有：

- `FulfillmentOrderService`：履约订单和状态；
- `FulfillmentReservationService`：逻辑库位库存预占；
- `FulfillmentPickingService`：订单级拣货任务和扫描；
- `FulfillmentPlatformActionService`：平台动作幂等；
- `FulfillmentShippingService`：面单、打包、批量签出；
- Ozon、Wildberries、Yandex 和人工订单平台适配器；
- `WarehouseBillingService`：仓库作业计费。

新增或拆分：

- `LogisticsProductService`：WMS 服务商物流产品管理和 ERP 可见范围；
- `FulfillmentLogisticsFeeService`：产品费用快照、WMS 调整和签出计费；
- 店铺默认物流产品配置接口；
- 当前订单路线和当前操作上下文接口；
- WMS 服务商物流产品收入查询。

旧销售出库单、旧自定义出库单、旧分货格和旧打包签出接口不得继续参与新版主链路。旧代码可以在迁移期间保留只读，但菜单和新业务入口必须只指向订单级履约模块。

## 16. 并发、幂等与错误处理

- 来源订单唯一键防止重复创建履约订单；
- 预占使用库存行锁和条件更新，防止超量预占；
- 下架、平台动作、取货扫描、打包和签出使用状态 CAS 或版本号；
- 平台动作按履约订单和动作类型唯一；
- SKU 扫描增量不能超过任务明细计划数量；
- 批量操作逐单事务，允许部分成功；
- 签出库存扣减和两类费用都有独立业务唯一键；
- 平台超时进入待对账状态，不盲目重复调用；
- 错误信息必须精确到订单和操作步骤。

## 17. 数据迁移

需要保留：

- 用户、角色、菜单和租户关系；
- WMS 服务商与 ERP 货主关系；
- 店铺和平台凭证；
- SKU、SKU 映射和平台订单；
- 仓库、分区、库位和逻辑库位库存；
- 当前订单级履约内核有效数据。

迁移步骤：

1. 备份数据库并提交当前 Git 基线；
2. 新增物流产品、店铺默认产品和履约快照字段；
3. 由 WMS 服务商创建首批物流产品；
4. 为店铺设置默认产品；
5. 测试履约订单补充产品快照或清理测试履约数据重新生成；
6. 停止旧销售出库、分货格和旧打包接口的新写入；
7. 完成新流程验收后再处理旧表。

## 18. 验收标准

- 不同 WMS 服务商的物流产品严格隔离；
- ERP 只能看到父级 WMS 服务商启用中的产品；
- 店铺默认产品能正确带出且订单允许临时修改；
- 履约订单保存名称、说明和费用快照；
- 只有 WMS 服务商能调整产品实际费用；
- 多订单下架允许部分成功；
- 取货页面明确展示库位、分区、SKU、数量和下一库位；
- 当前订单未完成不能操作下一单；
- 当前订单取齐后立即启用面单打印；
- 面单未复核不能打包；
- 当前订单打包完成后自动进入下一单；
- 已打包订单可以批量签出；
- 批量签出部分失败不影响成功订单；
- 签出物流信息不能为空；
- 库存只扣减一次；
- 物流产品费和仓库作业费分别且只生成一次；
- 费用付款方、收款方和收入归属正确；
- 签出后不产生物流轨迹同步任务。
