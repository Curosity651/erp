# 退货登记全局 SKU 与 Excel 导入设计

日期：2026-09-16

## 目标

海外仓平台登记实物退货时，操作员只输入或扫描系统生成的全局仓库 SKU，例如 `JHIN-ADNZ-007-QXM-02`。系统使用该编码唯一解析商品、货主和原始 SKU，不再要求操作员选择货主并填写原始 SKU。同时提供 Excel 模板下载和批量导入能力。

本次改造不改变退货状态机、货主处置、仓库执行、库存过账和计费逻辑。

## 当前问题

当前退货登记行要求填写 `erpTenantId + skuCode`。平台操作员需要先判断货主，再输入该货主范围内的 SKU，容易因货主选错而把退货登记到错误归属。

数据库中的原始 `skuCode` 只在货主范围内唯一；`WarehouseSkuCodeService` 使用唯一货主前缀和原始 SKU 生成仓库 SKU。货主前缀有数据库唯一约束，商品表有 `(tenant_id, sku_code)` 唯一约束，因此完整仓库 SKU 可以作为平台仓内的全局货物标识。

## 设计原则

1. 全局仓库 SKU 是操作员面对的唯一商品输入字段。
2. 商品和货主解析由后端权威执行，前端只展示解析结果。
3. Excel 导入只填充页面草稿，不直接创建退货单。
4. 最终提交时重新解析全部 SKU，防止导入后主数据变化或请求被篡改。
5. 任意一行无效时阻止整批提交，不产生部分退货单。

## 页面设计

### 退货登记弹窗

删除明细表中的“货主”选择列和“内部 SKU”自由输入列，替换为一个“全局 SKU”列。

操作员输入或扫描全局 SKU 后，前端以防抖方式调用批量解析接口（单行时请求数组只包含一个编码）。解析成功后在同一单元格中展示商品中文名、所属货主和原始 SKU；解析失败显示行内错误，且不允许提交。

保留以下字段：

- 实收数量，必填正整数；
- 平台订单号，选填；
- 退货原因，选填，缺省为 `OTHER`；
- 收货照片，选填，仍由页面逐行上传。

工具栏增加“下载模板”和“导入 Excel”按钮。手工添加、删除行的能力保留。

### 退货处理弹窗

商品列标题改为“全局 SKU”，只展示后端返回的 `warehouseSkuCode`。编码下方展示商品名称；退货单头部继续展示该处理单所属货主。新的退货登记数据必须具有全局 SKU，页面不再把原始 SKU 作为全局 SKU 的视觉兜底。

历史数据如果无法生成全局 SKU，后端详情接口返回明确错误，避免操作员对错误编码执行回库或销毁。

## 全局 SKU 解析

新增退货作业专用批量解析接口：

```http
POST /wms/return-qc/sku-resolve
Content-Type: application/json

{
  "warehouseSkuCodes": ["JHIN-ADNZ-007-QXM-02"]
}
```

接口权限沿用 `wms:return-qc:oper`，服务层继续校验当前身份必须为海外仓平台。

每个解析结果包含：

```json
{
  "warehouseSkuCode": "JHIN-ADNZ-007-QXM-02",
  "erpTenantId": 12,
  "ownerName": "JHIN",
  "skuCode": "ADNZ-007-QXM-02",
  "skuName": "商品名称",
  "matched": true,
  "error": null
}
```

后端按完整仓库 SKU 匹配 `货主唯一前缀 + '-' + 原始 SKU`。请求编码先去除首尾空格并按不区分大小写匹配，响应返回系统标准格式。空编码、重复编码、找不到商品或出现多条结果均返回对应编码的错误；单次最多解析 500 个编码。

## 登记接口调整

`ReturnReceiptDTO.Line` 的外部输入调整为：

```text
warehouseSkuCode  必填
receivedQty       必填
platformOrderId   选填
returnReason      选填
photoFileIds      选填
```

客户端不再提交 `erpTenantId` 和 `skuCode`。`ReturnQcService.registerReceipt()` 在事务内批量解析全局 SKU，得到真实 `erpTenantId` 和 `skuCode` 后再执行现有流程：

```text
全局 SKU
  → 唯一解析商品和货主
  → 校验货主可使用所选仓库
  → 按货主分组
  → 每个货主生成独立退货处理单
  → 写入退货明细
```

同一次登记中全局 SKU 不允许重复，比较时忽略大小写和首尾空格。接口保持事务原子性，任何一行失败都回滚整批。

## Excel 模板

使用项目已有的 ExcelJS 在浏览器生成和读取 `.xlsx` 文件，不新增运行时依赖。

工作簿包含两个工作表：

1. `退货商品导入`：操作员填写数据；
2. `填写说明`：字段说明、示例和退货原因可选值。

`退货商品导入` 的列为：

| 列 | 字段 | 必填 | 规则 |
|---|---|---|---|
| A | 全局 SKU | 是 | 完整仓库 SKU，文本格式 |
| B | 实收数量 | 是 | 大于 0 的整数 |
| C | 平台订单号 | 否 | 文本格式 |
| D | 退货原因 | 否 | `NOT_WANTED`、`DAMAGED`、`WRONG_ITEM`、`QUALITY_ISSUE`、`OTHER`，空值为 `OTHER` |

模板首行冻结并使用醒目表头，SKU 和平台订单号列固定为文本格式，退货原因列提供下拉验证。模板包含一行示例，导入器会识别并忽略未被修改的示例行。

## Excel 导入流程

1. 操作员选择 `.xlsx` 文件；
2. 前端读取第一个名为 `退货商品导入` 的工作表；
3. 校验表头、行数、必填值、数量、原因和重复 SKU；
4. 对有效行一次性调用全局 SKU 批量解析接口；
5. 所有 SKU 匹配成功后，将导入行替换当前页面明细草稿；
6. 操作员检查结果、补充照片并点击“确认登记”。

导入最多接受 500 条非空数据行。导入失败时保留页面原有草稿，错误弹窗按 Excel 行号列出问题；错误超过 20 条时显示前 20 条及剩余数量。空白行忽略。

## 错误处理

- 无法识别模板：提示重新下载最新模板；
- SKU 未匹配：提示行号和全局 SKU；
- SKU 重复：提示首次出现行和重复行；
- 数量不是正整数：提示对应行；
- 退货原因不在允许集合：提示对应行；
- 超过 500 行：拒绝导入；
- 解析接口失败：不修改当前草稿；
- 最终提交解析失败：不生成任何退货处理单。

## 代码范围

前端：

- `ReturnReceiptModal.vue`：全局 SKU 输入、解析结果、模板按钮和导入交互；
- `ReturnProcessModal.vue`：只显示全局 SKU；
- `api/wms/return-qc`：解析接口与 DTO 类型；
- 新增独立 Excel 模板/解析模块及对应测试；
- 四种平台语言补齐新增按钮、字段和错误文案。

后端：

- `ReturnQcController`：批量解析接口；
- `ReturnQcService`：权威解析、登记 DTO 转换与事务校验；
- `ReturnReceiptDTO`：改为接收全局 SKU；
- `WmsSkuLookupMapper`：完整仓库 SKU 查询；
- 新增解析请求/响应模型和服务测试。

不新增数据库表或迁移。

## 测试与验收

后端测试覆盖：

- 全局 SKU 正确解析为唯一货主和原始 SKU；
- 未匹配、重复及多匹配拒绝；
- 登记接口忽略客户端伪造归属的可能性，只采用后端解析结果；
- 多货主 Excel 数据仍按货主拆单；
- 任一行失败时事务不产生退货单。

前端测试覆盖：

- 模板列、说明工作表和下拉选项；
- Excel 正常解析；
- 错误表头、重复 SKU、非法数量、非法原因和超过 500 行；
- 匹配失败时不覆盖原草稿；
- 提交 payload 只包含全局 SKU，不包含货主和原始 SKU。

验收标准：操作员仅凭全局 SKU 可以完成单条登记和 Excel 批量导入，页面自动显示匹配货物与货主，最终生成的退货处理单归属正确，现有货主处置和仓库执行流程保持不变。
