# 仓库初始化后续任务

## 任务1：新建仓库自动初始化默认分区

**状态：** 已完成（2026-08-17）

### 目标

创建普通海外仓仓库成功后，自动生成以下四种默认分区：

| 分区类型 | 分区名称 | 可分配 |
| --- | --- | --- |
| `STANDARD` | 标准区 | 是 |
| `DEFECTIVE` | 不良品区 | 否 |
| `RETURN` | 退货区 | 是 |
| `TEMP` | 暂存区 | 否 |

### 实施要求

- 仓库保存与默认分区初始化必须在同一个数据库事务内完成。
- 复用 `WmsZoneService.initDefaultZones(warehouseId)`，不重复维护分区定义。
- 初始化必须幂等；重复调用不能产生重复分区。
- 任一默认分区创建失败时，仓库创建一并回滚。
- FBO 平台仓库是否需要这些物理作业分区保持现有规则，本任务只覆盖人工创建的普通海外仓仓库。

### 验收标准

- 新建普通仓库后，库位管理的分区选择立即显示四种默认分区。
- 每个仓库每种分区类型只有一条有效记录。
- 仓库创建失败或分区初始化失败时，不留下半成品仓库或部分分区。

## 任务2：逻辑库位状态与货架分配兼容改造

**状态：** 已完成（2026-08-17）

### 问题复现与根因

当前仓库 `CK1 / 李安` 已经存在两个有效逻辑库位：`A1-01`、`A2-01`，但仓库旧结构字段仍为：

- `rack_rows = 0`
- `rack_columns = 0`
- `location_generated = 0`

因此页面出现了互相矛盾的结果：

- 库位数按实际 `wms_location` 统计，正确显示为 2。
- “结构”仍读取旧 `rack_rows`，所以显示“未设计”。
- “状态”仍读取旧 `location_generated`，所以显示“未生成”。
- 货架分配页面把 `location_generated = 1` 作为打开预览和分配入口的前置条件，因此直接禁用了管理入口。

`location_generated` 只会由旧版“固定行列批量生成库位”流程设置。新版库位是人工按排动态添加，不再经过旧生成器，所以继续使用这个字段判断必然会误判。

### 处理原则

- 新版页面以实际逻辑库位为唯一事实来源，不再用 `rack_rows`、`rack_columns`、`location_generated` 判断是否可用。
- 不通过把当前仓库的 `location_generated` 强行改成 1 来掩盖问题；否则以后每个手工添加库位的新仓库都会再次出现同样问题。
- 货架分配仍然按“排”分配给 WMS 服务商，不改为逐个库位分配。
- 公共共享库位不参与排分配，也不继承某一家 WMS 服务商的专属权限。

### 后端修改

1. 为库位管理仓库摘要增加三个基于实际数据计算的字段：
   - `actualRackCount`：全部有效逻辑库位的排号去重数量，用于库位布局展示。
   - `assignableRackCount`：有效且非公共共享逻辑库位的排号去重数量，用于货架分配入口判断。
   - `locationConfigured`：仓库是否至少存在一个有效逻辑库位。
2. 使用一次分组统计查询返回各仓库的实际排数和库位数，避免仓库列表逐仓查询造成 N+1。
3. `WarehouseStructureVO` 保留旧结构字段用于兼容旧接口，但新版库位管理和货架分配不再依赖这些字段。
4. 货架分配预览改为直接从实际逻辑库位提取排号；只要某排存在可分配逻辑库位，就能显示和分配，不要求 `location_generated = 1`。
5. 新增统一的“可分配库位/排”查询口径：
   - `deleted = 0`
   - `is_virtual = 0`（兼容现有数据定义）
   - `public_shared = 0`
6. 货架分配创建时使用同一口径校验排号，防止前端可见、后端却提示排不存在，也防止把公共暂存区域分配给单个服务商。
7. 服务合同中选择实际货架的逻辑同步采用同一可分配排口径，保证合同资金和货架分配不会出现两套排列表。
8. 当前仓库无需补写旧生成状态；代码上线后会依据现有 `A1-01`、`A2-01` 自动识别为“已配置，可分配”。

### 前端修改

1. 库位管理列表：
   - “结构”改为“库位布局”。
   - 有库位时显示“2 排 · 2 库位”等实际结果。
   - 无库位时显示“未配置”。
   - 状态从“已生成/未生成”改为“已配置/未配置”。
2. 筛选条件从“库位生成状态”改为“库位配置状态”，使用 `locationConfigured` 筛选。
3. 货架分配列表取消 `locationGenerated === 1` 的入口限制：
   - `assignableRackCount > 0` 时可进入管理并加载实际排预览。
   - 没有任何可分配库位时禁用入口，并提示“请先在库位管理中添加非公共库位”。
4. 分配情况按实际排显示“总排数、已分配、合同预留、未分配”，并继续使用自然顺序 `A1、A2、A10`。
5. 公共共享库位不显示为可分配货架；它仍可在库位管理和库位库存中正常查看、使用。
6. 清理页面上“生成库位”“未设计”等旧几何结构文案，避免工作人员误以为还需要执行一次生成操作。

### 数据兼容

- 不删除 `rack_rows`、`rack_columns`、`location_generated`，避免影响尚未清理的旧接口和历史审计代码。
- 新逻辑不回填这些旧字段，它们不再代表新版逻辑库位的真实状态。
- 已存在的货架分配记录继续有效；排号仍通过 `warehouse_id + rack_no` 关联。
- 公共共享库位即使与普通库位处于同一仓库，也不会单独形成可分配排。

### 测试与验收

1. 仓库旧字段均为 0，但存在 `A1-01`、`A2-01` 时：
   - 库位管理显示“2 排 · 2 库位”。
   - 状态显示“已配置”。
   - 货架分配入口可以点击。
2. 货架分配预览显示 `A1`、`A2`，可选择空闲排并分配给 WMS 服务商。
3. 分配完成后列表统计和排详情立即刷新，服务合同可选排与货架分配可选排一致。
4. 只有公共共享库位的仓库不允许进行专属排分配，但公共库位仍可正常用于库存业务。
5. 完全没有库位的仓库显示“未配置”，分配入口禁用并给出准确提示。
6. 排号按自然顺序显示，验证 `A1、A2、A10` 不再按字符串顺序错排。
7. 执行后端定向测试、前端类型检查和生产构建，并在浏览器验证库位管理、货架分配、合同资金三个页面。
