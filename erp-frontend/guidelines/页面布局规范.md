# 前端页面布局规范

> 适用范围：本项目所有「列表型」管理页面（增删改查）。范例基准：`views/wms/purchase-order/`。
> 与《UX 规范.md》配套：UX 规范管视觉/交互细节，本规范管页面骨架与组件选型。

## 一、整体结构：一页三段

```
XxxPage.vue（只做编排）
├─ ① 搜索栏      XxxPageSearch.vue      —— a-card 包裹的查询表单
├─ ② 列表        ProTable               —— 工具栏(新建/导出) + 数据行 + 操作列
└─ ③ 详情/表单   XxxDetailDrawer.vue    —— 详情抽屉
                 XxxFormModal.vue       —— 新建/编辑弹窗
```

主页面只负责把三段拼起来 + 持有 `searchParams`、`tableRequest`、各类 `handleXxx`；搜索、详情、表单都拆成**独立子组件**。

## 二、① 搜索栏 `XxxPageSearch.vue`

- 外层 `<a-card :bordered="false" style="margin-bottom:16px" :body-style="{paddingBottom:0}">`。
- `a-form :model="formModel" :label-col="{ md:{span:6} }"` + `a-row :gutter="[16,8]"`。
- 每个查询项一个响应式列：`<a-col :xl="6" :lg="8" :md="12" :sm="24">`（一行最多 4 个，窄屏自适应换行）。
- 输入框统一 `allow-clear`；**实体若有状态字段，必须提供状态 `a-select` 筛选**（`allow-clear` + `:options`）；日期用 `a-range-picker value-format="YYYY-MM-DD"`。
- 最后一列放 `<search-actions :loading @search @reset />`（查询 / 重置）。`reset` 清空字段后自动再查询一次。
- props：`{ loading?: boolean }`（接列表 loading）；emits：`(e:'search', params)`。

## 三、② 列表 `ProTable`

```ts
import ProTable from '#/table'
import type { ProColumns, ProTableInstanceExpose, TableRequest } from '#/table'
```

- `<pro-table ref header-title row-key="id" :request="tableRequest" :columns size="middle" :scroll="{x:…}">`。
- `tableRequest`：`const p = mergePageParam(params,sorter,filter); return pageXxx({ ...p, ...searchParams })`。
- **工具栏** `#toolBarRender`：`<new-button v-if="hasPermission('模块:资源:add')" @click="handleNew"/>`（可加导出等）。
- **信息列**：把强相关的多个字段聚成一个「信息块」列（主标识做成可点 `<a>` 打开详情），不要一字段一列平铺。
- **操作列**：`{ key:'operate', title:'操作', align:'center', fixed:'right', width:~140 }`，内容用 `<operation-group>`：
  - `查看`（常驻，打开详情抽屉）；
  - `编辑`（`v-if="hasPermission(...) && 状态允许"`，简单实体可直接打开编辑弹窗）；
  - 多余动作收进 `<a-dropdown>` 的「更多 ▾」：状态流转动作 + `<delete-text-button @confirm="handleDelete">`（自带二次确认）。

## 四、③ 详情 / 新建-编辑

- **详情**：`XxxDetailDrawer.vue`，对外暴露 `open(id)`；父页 `detailDrawerRef.value?.open(record.id)`。
- **新建/编辑**：统一用**弹窗** `XxxFormModal.vue`（`a-modal` + `a-form`）：
  - 对外暴露 `openCreate()` / `openEdit(record)`；`@success` 通知父页 `reloadTable()`。
  - 提交走 `doRequest(saveXxx(data), { successMessage:'保存成功', onSuccess })`。
  - **例外**：表单极复杂（如采购单含多明细 + 文件 + 付款）可用整页 `FormPage` + 路由；其余一律弹窗。

## 五、公共组件 / 工具（统一复用，禁止自造）

| 用途 | 用什么 | 来源 |
|---|---|---|
| 列表 | `ProTable` | `#/table` |
| 新建按钮 | `NewButton` | `@/components/Button` |
| 删除/二次确认按钮 | `DeleteTextButton` / `ConfirmTextButton` | `@/components/Button` |
| 操作列容器 | `OperationGroup` | `@/components/Operation` |
| 搜索 查询/重置 | `SearchActions` | 全局组件 |
| 权限判断 | `useAuthorize().hasPermission('模块:资源:动作')` | `@/hooks/permission` |
| 接口动作+提示+回调 | `doRequest(api(), { successMessage, onSuccess })` | `@/utils/axios/request` |
| 分页参数合并 | `mergePageParam(params,sorter,filter)` | `@/utils/page-utils` |
| 列表刷新 | `tableRef.value?.actionRef?.reload(resetPageIndex)` | — |
| 身份判断（多租户裁剪） | `useUserStore().userInfo?.identityType` | `@/stores/user-store` |

## 六、约定细则

- 组件名：`defineOptions({ name:'XxxPage' })`，必须多词（避免 `vue/multi-word-component-names`）。
- 写库存/写敏感数据的入口，按身份门控（C4：货主只读）：`v-if="userInfo?.identityType !== 'ERP_USER'"`。
- 金额红色加粗、次要信息灰色小字、可点主标识蓝色——见 `purchase-order` 的 `<style scoped>`。
- 列表行禁止把"编辑/删除"裸露成一排按钮过多；超过 2 个动作收进「更多 ▾」。

## 七、非列表型页面（专项可视化）

货架分配二维预览、库位生成等**专项页面**不强套 ProTable，但**搜索/筛选区、操作按钮、二次确认、权限门控、组件命名**等公共约定同样适用，保持与全项目一致的观感。
